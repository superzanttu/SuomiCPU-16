= SC-16 architecture modernization plan
:toc: left
:toclevels: 2
:experimental:

== Goal and design boundaries

This plan evolves SC-16 into a bootable computer architecture for a protected,
preemptively multitasking operating system with virtual memory. It replaces
emulator-side program compilation and block-oriented virtual disks with
prebuilt programs and folder-backed disks.

Implement the work in stages. Preserve the existing emulator, programs, game
window, and serial Bug Monitor during the transition. Do not claim process
isolation until the MMU enforces user/kernel memory permissions.

=== Current implementation baseline

This baseline describes the emulator today, not the intended OS architecture.
The checklist below tracks the migration from these behaviors to the target
contracts.

* The guest is byte-addressed, uses 16-bit instructions and eight general
  registers, and has up to 1 GiB of memory. The CPU supports 30-bit addresses
  and big-endian multi-byte values. A loaded program starts at its image entry
  point; CPU construction initializes the PC to zero and the stack pointer to
  the top of configured memory.
* The emulator's BIOS selects a source program from +modules/+ and compiles it
  during startup. Applications run in the game window; the optional Bug Monitor
  displays emulator logs and guest serial output from the UART-style device.
  It is separate from the text-mode BIOS.
* Data disks are JSON-backed 256-byte block devices. They are not boot media,
  and the BIOS loads executable images from module sources rather than disks.
* The CPU has keyboard, RTC, and instruction-count timer interrupts with fixed
  vectors. Interrupts save PC and flags on the current stack; the CPU has no
  privilege modes, protected address spaces, page tables, or hardware task
  contexts.
* The assembler and CPU provide binary32/binary64 instructions. The C compiler
  now lays out and initializes global floating objects using those formats, but
  runtime floating expressions, conversions, automatic objects, calls, and
  returns remain unsupported. Existing math routines still use binary16.
  See link:c90_todo.adoc[+c90_todo.adoc+] for the compiler work.

== Existing roadmap integration

* This document owns the SC-16 architecture, boot, disk, privilege,
  multitasking, memory-management, syscall, and target-ABI work.
* C90 language and compiler work remains in
  link:c90_todo.adoc[c90_todo.adoc]. Its hosted-runtime and executable-image

== Implementation checklist

Checklist status: [x] completed; [ ] planned.

=== Phase 0 — Maintain target ABI and CPU compatibility

* [x] *Implement the 30-bit control-flow ABI* (+sc16-control-flow-abi+)
** Store return PCs as four big-endian bytes; +RET+ and +RTI+ restore all 30 address bits.
** Place the first function parameter four bytes above the stack pointer and
   update assembly-library argument offsets.
** Encode far control flow in six bytes and add +JMPRP+ / +CALLRP+ for full
   30-bit addresses.
** Add +LDI30+ (with +LDI19+ / +LDA+ compatibility aliases) for full-width
   addresses.

* [ ] *Define and maintain the C target floating-point model*
  (+c90-float-model+)
** [x] Define IEEE-754 binary32 +float+ and binary64 +double+ / +long double+
   representations, sizes, byte order, alignment, rounding, and special-value
   behavior in +c90_target_abi.adoc+.
** [x] Use target sizes for +sizeof(float)+, +sizeof(double)+, and
   +sizeof(long double)+; emit binary32/binary64 global scalar and array
   initializers in big-endian object representation.
** [x] Reserve target-sized stack storage for uninitialized automatic floating
   scalars and arrays; report their correct +sizeof+ values.
** [ ] Implement initialized automatic floating objects, runtime loads/stores,
   literal expressions, conversions, arithmetic, comparisons, and
   floating-point function arguments and results.
** [x] Verify +float.h+ limits against the target model and test binary32 /
   binary64 maximum, minimum-normal, epsilon, subnormal, and tie-rounding
   initializer representations, including promotion of a rounded +float+
   constant to +double+.
** [ ] Add runtime floating-point execution tests for arithmetic, conversions,
   comparisons, calls, and returns.

* [x] *Provide binary32/binary64 CPU operations* (+c90-float-isa+)
** [x] Add arithmetic, ordered comparisons, conversions, negation, and square
   root instructions.
** [x] Implement register encoding, rounding, subnormals, signed zero,
   infinities, NaNs, and comparison flags.
** [x] Add assembler and execution regressions.
** *Depends on:* +c90-float-model+.

* [ ] *Validate floating-point execution and ABI behavior*
  (+c90-float-validation+)
** Test numeric boundaries, rounding, casts, constants, calls, and returns.
** Compare CPU results against an independent reference.
** *Depends on:* +c90-float-backend+ in
   link:c90_todo.adoc[+c90_todo.adoc+].

* [ ] *Validate the complete C target ABI* (+c90-abi-conformance+)
** Verify data types, representations, alignment, pointers, conversions,
   stack frames, and calling conventions.
** Test C-visible memory, control flow, and floating-point behavior.
** Update +c90_target_abi.adoc+ only from verified results.
** *Depends on:* +c90-float-validation+ and the C compiler tasks
   +c90-indirect-calls+, +c90-pointer-qualifiers+, +c90-bitfield-codegen+,
   +c90-linkage-storage+, and +c90-initializers+ in
   link:c90_todo.adoc[+c90_todo.adoc+].

* [ ] *Define C90 bit-field target layout* (+c90-bitfield-layout+)
** Specify allocation-unit size, bit order, signedness, alignment, packing,
   boundary crossing, and zero-width fields.
** Define interactions with +sizeof+, unions, padding, and +offsetof+.
** Document ABI choices and add layout tests.

=== Phase 1 — Define architecture, disk, and image contracts

* [ ] Write an SC-16 architecture specification covering reset state, address
  width, byte order, instruction behavior, exceptions, privilege transitions,
  interrupts, memory translation, device access, and the text-display interface
  used by firmware.
* [ ] Specify the character-cell display contract for firmware and guest
  software, including screen dimensions, character encoding/font, cursor and
  scrolling behavior, color attributes, and display-mode ownership. Keep text
  output distinct from serial diagnostics and guest pixel graphics.
* [ ] Define the privilege model: reset enters kernel mode; user mode cannot
  execute privileged instructions, alter control registers, modify interrupt
  state, access kernel-only mappings, or access protected devices.
* [ ] Define exception and interrupt entry/return frames, including the saved
  privilege level, PC, flags, stack selection, and the behavior for faults
  during entry or return.
* [ ] Define a versioned disk metadata JSON schema. Specify
  required and optional fields, validation errors, encoding, path rules, file
  lengths, virtual capacity, disk-wide read/write mode, the read-only file
  list, required executable names, and metadata compatibility/version handling.
  The executable and its mode are selected by the fixed +main.bin+ / +kernel.bin+
  rule, not by a metadata field.
* [ ] Define a standard executable image format and offline build pipeline.
  Include entry point, load segments, permissions, alignment, relocation policy,
  and rejected malformed-image cases.
* [ ] Coordinate executable-image, calling-convention, and process-entry
  decisions with the target ABI in +c90_target_abi.adoc+. Update the ABI
  document only after implementation and conformance tests confirm behavior.
* [x] Document the current architecture and migration incompatibilities in the
  baseline above.
  Keep this specification authoritative for implementation and tests.

=== Phase 2 — Boot through system BIOS

* [ ] Change CPU reset/power-on state to enter kernel mode at a documented
  firmware entry point with interrupts disabled and a defined stack/control
  state.
* [x] Implement the BIOS character-cell text renderer in the emulator's main
  window. Use bright green text on black with enlarged fixed-width characters
  and no glow or post-processing; do not open a separate terminal window.
* [ ] Implement a guest-visible character-cell text display if the finalized
  architecture does not already provide one, for use by guest software. The
  BIOS must continue rendering in the emulator's main window.
* [x] Preserve the existing game window and optional serial Bug Monitor after
  boot; switching the BIOS to text mode must not force applications into a
  text-only display mode.
* [x] Provide dedicated emulator logging methods and guest C functions for
  DEBUG, INFO, WARN, and ERROR records over the serial output in
  +lib/bug_monitor.h+. Route emulator lifecycle and device errors to the Bug
  Monitor; preserve raw guest serial output and the existing serial input path.
* [ ] Use one emulator-wide +bios.bin+ as firmware; do not require a BIOS or
  +boot.bin+ on each disk. Separate emulator hardware initialization from
  firmware execution, then transfer control to the BIOS at the documented
  kernel-mode entry point. BIOS must not compile or assemble guest programs.
* [ ] Implement BIOS disk discovery and text-mode disk selection. After
  selection, validate disk metadata and require exactly one boot
  executable: if only +kernel.bin+ exists, load it in KERNEL mode; if only
  +main.bin+ exists, load it in USER mode. If both files exist, or if neither
  exists, report +NOT_BOOT+. Metadata does not choose the executable or its
  mode.
* [ ] Treat the presence of +kernel.bin+ as authorization to execute that
  disk-provided image in KERNEL mode. Document this trust model clearly; disk
  metadata and user-mode programs must not be able to change the BIOS rule.
* [ ] Add boot tests for cold reset, common BIOS startup, text-mode rendering
  and selection, direct executable loading, both launch modes, both
  +NOT_BOOT+ cases, invalid images, and recoverable boot failures.

=== Phase 3 — Replace block disks with folder-backed filesystems

* [ ] Design a disk abstraction backed by one explicitly configured host folder
  per disk. A disk's files and subfolders appear as its guest-visible
  filesystem; do not emulate sectors, cylinders, blocks, or block pointers.
* [ ] Implement metadata parsing and disk discovery, including disk identity,
  label, virtual capacity, disk-wide read-only/read-write mode, and the list of
  protected files.
* [ ] Implement guest filesystem operations for listing directories, reading
  files, writing files, creating directories, deleting/renaming entries, and
  querying metadata, subject to the finalized syscall/device interface.
* [ ] Confine normalized guest paths to the mounted disk root. Reject traversal,
  invalid paths, unsupported file types, and host I/O failures explicitly.
* [ ] Enforce disk-wide read-only status and the metadata-listed per-file
  read-only set. Protected files cannot be written, replaced, deleted, renamed,
  or otherwise mutated; do not add general user/group/owner access-control
  semantics.
* [ ] Define used capacity as the sum of regular-file byte lengths, excluding
  directory and metadata overhead, and enforce the declared virtual-capacity
  hard limit for writes, copies, and file growth. Reject non-regular host-file
  types and host I/O failures explicitly.
* [ ] Migrate existing JSON block disks and module data into folder-backed disk
  images with a documented conversion tool or import path; keep all source
  files and source disk images.
* [ ] Remove block-level disk device behavior only after replacement APIs and
  migration are covered by tests. Update disk editor, BIOS selection, examples,
  and documentation to use disks rather than data-disk blocks.

=== Phase 4 — Enforce kernel/user privilege

* [ ] Add a CPU privilege-state representation and a reliable kernel-mode reset.
* [ ] Classify instructions, control registers, interrupts, and MMIO regions as
  privileged or user-accessible. Raise a defined exception on forbidden access.
* [ ] Add a protected transition from kernel to user mode with a user PC and
  user stack; prevent user code from forging or bypassing that transition.
* [ ] Add a protected transition back to kernel mode for exceptions, interrupts,
  and software system calls, using a kernel stack rather than trusting the
  current user stack.
* [ ] Implement exception vectors and interrupt descriptor handling with
  privilege checks, nested-interrupt policy, acknowledgement, and a defined
  return-from-interrupt instruction or frame contract.
* [ ] Add tests proving that kernel operations continue to work and that
  user-mode code cannot modify kernel state, execute privileged operations, or
  reach protected memory/devices.

=== Phase 5 — Add interrupts and preemptive scheduling

* [ ] Specify an interrupt descriptor table (IDT): descriptor layout, vector
  numbering, gate types, privilege rules, installation, and invalid-vector
  behavior. Migrate the existing fixed vectors to the specified table.
* [ ] Specify and implement a programmable interval timer (PIT) with defined
  clock source, frequency/divisor behavior, interrupt generation, masking, and
  acknowledgement. Keep timer behavior deterministic in tests and headless
  execution.
* [ ] Add timer-driven preemption and a documented complete task context,
  including all registers, flags, PC, privilege state, address-space identity,
  and kernel/user stack state.
* [ ] Implement kernel scheduler primitives for creating a task context,
  switching contexts, yielding, exiting, and selecting the next runnable task.
* [ ] Add tests with multiple tasks that demonstrate timer preemption, explicit
  yield, register/flag preservation, blocked/woken tasks, and clean task exit.

=== Phase 6 — Implement the MMU and protected virtual memory

* [ ] Specify an MMU with the existing 30-bit address width, 4 KiB pages, and
  two-level paging with 512 32-bit entries per directory/table. Use 9 directory
  bits, 9 table bits, and 12 page-offset bits; each directory/table occupies
  2 KiB and each page-table entry contains an 18-bit physical frame number and
  flags. Define control registers, permissions, page-fault causes, and
  supervisor translation rules.
* [ ] Define and implement the page directory and page table entry formats,
  including present, read/write, user/supervisor, and any required execute/cache
  bits.
* [ ] Implement page translation and page-fault exceptions for instruction
  fetches, data reads/writes, and user/kernel permission violations.
* [ ] Add address-space control registers and a safe address-space switch
  operation. Define translation-cache/TLB behavior even if the first emulator
  implementation has no performance cache.
* [ ] Implement kernel page-frame allocation and freeing, page-table management,
  and memory accounting.
* [ ] Establish and test the kernel's physical-memory identity mapping and
  transition to normal virtual mappings. Specify which devices are mapped and
  ensure user mappings cannot access kernel or protected MMIO pages.
* [ ] Add kernel mapping helpers for allocation, mapping, unmapping, and
  permission changes. Define page-fault recovery versus process termination.
* [ ] Test isolation between processes, guard pages, invalid/unmapped accesses,
  read-only pages, user/supervisor permissions, address-space switching, and
  physical-frame reuse.

=== Phase 7 — Define the system-call ABI and services

* [ ] Specify the software-interrupt or dedicated system-call instruction,
  syscall number and argument convention, return/error convention, privilege
  transition frame, and ABI versioning.
* [ ] Define how the C runtime and hosted C library use the syscall ABI.
  Preserve standard C interfaces where appropriate, document SC-16 extensions,
  and distinguish unavailable host services from implemented file operations.
* [ ] Implement syscall dispatch with validated user pointers, bounded
  transfers, defined errors, and no direct trust of user-supplied addresses.
* [ ] Implement +sys_spawn+ to load an executable into a new protected address
  space and create a task, enforcing the specified privilege-transition rules.
* [ ] Implement +sys_exit+, +sys_yield+, and +sys_getpid+.
* [ ] Implement +sys_mmap+ with page permissions and process ownership rules.
* [ ] Implement +sys_read+ and +sys_write+ for the console and folder-backed
  disk filesystem, with explicit file-handle, path, and partial-I/O behavior.
* [ ] Implement +sys_sleep+ using timer ticks and a blocked-task wakeup queue.
* [ ] Implement +sys_wait+ with child-process status collection and defined
  behavior for invalid/non-child process IDs.
* [ ] Specify and implement +sys_sep_op+ for semaphore operations, including
  operation codes, semaphore ownership and lifetime, blocking/wakeup behavior,
  and error handling.
* [ ] Add ABI-level tests for valid calls, invalid syscall numbers, invalid or
  unmapped user pointers, permissions, interrupted calls, and task lifecycle.

=== Phase 8 — Move applications to bootable disk images

* [ ] Convert each runnable module into a disk folder/image containing
  +disk.json+, exactly one of +main.bin+ or +kernel.bin+, and its runtime
  assets/data. Use the emulator-wide BIOS; do not package per-disk +bios.bin+
  or +boot.bin+.
* [ ] Move assembly and C compilation out of BIOS/emulator startup. Provide
  offline build commands that compile and link programs, produce the specified
  executable image, and package the disk manifest and files.
* [ ] Preserve +sc16build+ and the Rust compiler as offline developer/build
  tools; ensure disk boot and program launch consume prebuilt images and never
  invoke a compiler or assembler inside the guest BIOS.
* [ ] Reconcile C90 hosted execution and file-backed +stdio+ work in
  +c90_todo.adoc+ with the folder-backed disk and +sys_read+/+sys_write+ ABI.
  Implement hosted file streams only after those interfaces and error semantics
  are stable.
* [ ] Update module discovery and BIOS UI to enumerate disks and show manifest
  metadata in the text-mode BIOS rather than scanning C source files and
  compiling selected modules.
* [ ] Update direct-program launch, +--disk+, reset/reboot, gallery, examples,
  build scripts, CI, and test fixtures to use disk images and the standard boot
  flow.
* [ ] Remove the old in-emulator assembler/compiler boot path after all
  supported applications have migrated and equivalent offline tooling is
  verified. Preserve legacy source, tools, and data files; move or archive
  them rather than deleting them.
* [ ] Update user and architecture documentation, including disk creation,
  offline compilation, boot troubleshooting, privilege modes, interrupts, MMU,
  and syscall ABI.

=== Phase 9 — Verify a protected multitasking OS

* [ ] Build a minimal kernel disk that boots through the emulator-wide BIOS,
  initializes protected memory and the PIT/IDT, and enters user mode.
* [ ] Run at least two isolated user tasks that are preempted and scheduled
  without losing register state or allowing one task to access the other's
  memory.
* [ ] Demonstrate the syscall lifecycle (+spawn+, +yield+, +sleep+, +wait+,
  file/console I/O, and +exit+) from user programs.
* [ ] Add end-to-end tests for cold boot through disk selection, kernel startup,
  user launch, task switching, protection faults, and clean shutdown/reboot.
* [ ] Publish the supported machine/boot/disk/syscall versions and explicitly
  list any unimplemented features before describing the architecture as ready
  for general-purpose operating systems.
