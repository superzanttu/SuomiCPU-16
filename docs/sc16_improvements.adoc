= SC-16 architecture modernization plan
:toc: left
:toclevels: 2
:experimental:

== Goal and design boundaries

This plan records the SC-16 hardware and runtime migration to a bootable
computer architecture for a protected, preemptively multitasking operating
system with virtual memory. The current design uses prebuilt programs and
folder-backed disks; guest source compilation and legacy block-disk loading
are not runtime features.

=== Current implementation baseline

This baseline describes the emulator today, not the intended OS architecture.
The checklist below tracks the migration from these behaviors to the target
contracts.

* The guest is byte-addressed, uses 16-bit instructions and eight general
  registers, and has up to 1 GiB of memory. The CPU supports 30-bit addresses
  and big-endian multi-byte values. A loaded program starts at its image entry
  point; CPU construction initializes the PC to zero and the stack pointer to
  the top of usable RAM, below the reserved high device aperture.
* The required guest-resident +firmware/bios.bin+ selects an ID-named folder disk under
  +disks/+ through a supervisor firmware service, validates its metadata, and
  loads its prebuilt boot image without compiling source. Explicit source
  launches remain a developer workflow.
  Applications run in the game window; the optional Bug Monitor
  displays emulator logs and guest serial output from the UART-style device.
  It is separate from the text-mode BIOS.
* Runtime storage uses folder disks with guest filesystem access. Archived
  JSON-backed 256-byte block images are inert and unsupported.
* The CPU has supervisor and user modes, fixed interrupt vectors, an MMU with
  user/kernel page permissions, protected device access, and keyboard, RTC,
  and timer interrupts. Guest kernels can schedule tasks with interrupt and
  address-space switching; the optional `STARTU` extension also provides
  emulator-backed user-task scheduling.
* The assembler and CPU provide binary32/binary64 instructions. The C compiler
  now lays out and initializes global floating objects and supports sized
  automatic floating storage plus constant initializers using those formats.
  General binary32 support includes scalar, indexed-array, and float-pointer
  loads/stores; arithmetic, comparisons, conditions, and conditional
  expressions; signed/unsigned 16-bit conversions; and binary32 results.
  Binary64 runtime support now covers tested scalar and
  pointer-array access, arithmetic, comparisons, and signed 16-bit conversion.
  Fixed-signature calls use a shared scalar stack layout, with tested mixed
  integer/pointer/floating arguments, multiple floating parameters, nested
  calls, and recursion. Typed C90 conversions, complete 32-bit conversions,
  default argument promotions, and complete floating call compatibility
  remain incomplete. Existing math routines still use binary16. See
  link:c90_todo.adoc[+c90_todo.adoc+] for the remaining compiler work.
