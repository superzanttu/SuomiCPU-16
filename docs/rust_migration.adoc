= Rust implementation status

The Python-to-Rust migration is complete for the repository's supported
emulator, compiler, build, and developer-tool workflows. There are no +.py+,
+.pyc+, or +.pyo+ files and no Python package/dependency manifests in the
repository. Runtime, compiler, tools, tests, and CI use Rust; unsupported C
syntax or semantics produce a Rust diagnostic, with no compatibility-compiler
fallback.
The runtime requires the checked-in emulator-wide +firmware/bios.bin+ image. The
supported application disks are prebuilt with the Rust build tool and contain
their compiled images and local runtime assets.

Migration completion does not imply full C90 conformance. The C compiler
remains a partial C90 implementation; see link:c90_todo.adoc[+c90_todo.adoc+] and
link:c90_target_abi.adoc[+c90_target_abi.adoc+] for the separate language and ABI
work. The browser build is also not yet a standalone web release; see the
browser-build note in link:../README.adoc[+README.adoc+].

The graphics device now uses the high device bank and protected syscall 24.
The former low-address graphics coprocessor, layered renderer, and 3D command
route are retired; current graphics regressions exercise the bank and syscall
interfaces instead.

Run the Rust validation suite and build every bootable BIOS program with:

[source,console]
----
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo check --locked --target wasm32-unknown-unknown
cargo run --locked --bin sc16build -- build-programs
cargo run --locked --bin sc16build -- install-programs
----
