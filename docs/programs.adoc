= Building and installing SC-16 programs
:toc:

== Layout

The repository is one Cargo package. Rust emulator implementation is in
+src/emulator/+, the assembler in +src/assembler/+, the C compiler in
+src/c_compiler/+, and shared offline command-line tools in +src/tools/+.
Crate-level module names and command-line binary names are unchanged.
Shared guest headers live in +toolchain/include/+ and their C/assembly
implementations in +toolchain/runtime/+. BIOS source, image, and shared fonts
live in +firmware/+. Writable host settings remain in +config/bios.json+.

Each installable workload has a canonical lowercase +programs/<slug>/+
directory, an explicit +program.json+, guest sources/local headers in +src/+,
and any program-specific tools in +tools/+. Existing program documentation
lives in its +docs/+ directory. Seed disk files are in +assets/disk/+;
editable source artwork may live separately in +assets/gfx/+.
Tank-16's Rust tools remain Cargo binaries in the same package.

SisuOS is an ordinary catalog entry under +programs/sisuos/+, not an emulator
component. Its C shell, C child demo, and assembly bootstrap are declared in
its manifest. Educational +examples/+ are fixtures, not installed programs;
tests may compile and execute them.

== BIOS, program, and disk workflows

Run commands from the repository root with Rust/Cargo on PATH. The shared BIOS
is assembled separately from guest programs:

[source,powershell]
----
cargo run --bin sc16build -- build-bios
cargo run --bin sc16build -- build-program sisuos
cargo run --bin sc16build -- install-program sisuos
.\scripts\build-install.ps1 sisuos
.\scripts\build-install.ps1 tank-16 -Start
----

+build-bios+ assembles +firmware/bios.asm+ into +firmware/bios.bin+ by default.
The optional source and output arguments can select other paths. +build-program+
compiles the manifest-selected sources into +build/programs/<slug>/+ without
changing the installed disk. For SisuOS this creates the protected kernel and
demo images with the manifest and package ownership record.

The BIOS command reports its selected source and output; the default success
message has this form:

[source,console]
----
Built shared BIOS firmware <source> -> <output>
----

Successful program builds and installs report their package and resolved output
path, for example:

[source,console]
----
Built sisuos -> <repository>/build/programs/sisuos
Installed sisuos -> <repository>/disks/sisuos
----

+install-program+ builds first, then safely installs the package into its
configured +install_disk+ (or +disks/<slug>/+ when that optional field is
omitted). It preserves unrelated writable disk files and settings, updates
unchanged package-owned files, and reports conflicts instead of overwriting
modified package-owned files. The backend accepts all current program
manifests, and packages compatible sources together with their declared
+assets+ trees. Some older guest sources still include removed graphics or
disk headers, so their builds fail with an explicit compiler diagnostic until
those programs are migrated to current interfaces.

To open the BIOS selector and preselect SisuOS:

[source,powershell]
----
cargo run --bin suomicpu16 -- --disk sisuos
----

To launch the checked-in disk directly:

[source,powershell]
----
.\run.ps1 .\disks\sisuos
----

The BIOS launches prebuilt images only. The Windows +run.ps1+ launcher rebuilds
the shared BIOS when it is missing or older than its assembly source. It can
also compile a supplied +.asm+ or supported +.c+ source to a temporary image
before starting the emulator; that temporary image is removed when the emulator
exits.

For an educational fixture or one-off boot disk, +sc16build package-disk+
builds source into a new destination and refuses to overwrite an existing
destination:

[source,powershell]
----
cargo run --bin sc16build -- package-disk examples/minimal_kernel.asm disks/KERN0001 MinimalKernel 65536 --kernel
----

Use +--kernel-user-c <source.c>+ with +--kernel+ to embed a C user program in
an assembly kernel. The fixed boot names are +kernel.bin+ for supervisor
startup and +main.bin+ for user startup; the manifest cannot override that
rule. See link:sc16_disk_format.adoc[the folder-disk contract] for the complete
manifest and boot behavior.

== Helper scripts and command-line reference

The repository-root PowerShell wrapper builds and installs one selected
manifest package. Use +-Start+ to launch its configured installed disk after a
successful install:

[source,powershell]
----
.\scripts\build-install.ps1 sisuos
.\scripts\build-install.ps1 tank-16 -Start
----

+scripts/build-install.ps1+ calls the shared Rust +install-program+ command;
it does not invoke program-specific build scripts. The backend builds into
+build/programs/<slug>/+ and safely installs into the configured disk folder.

Use +sc16build --help+ to list the supported offline commands, including
+build-bios+, +build-program+, +install-program+, +build-programs+,
+install-programs+, +package-disk+, and the explicit disk-migration command.
Use +suomicpu16 --help+ for the emulator invocation forms:

[source,console]
----
Usage: suomicpu16 [--fullscreen] [--disk ID] [--net-port PORT] [IMAGE.bin|IMAGE.sc16img|DISK_FOLDER]
       suomicpu16 --headless [--disk ID] [--net-port PORT] IMAGE.bin|IMAGE.sc16img|DISK_FOLDER
----

Starting without a program opens the BIOS selector; +--disk ID+ preselects a
folder disk for BIOS boot. +--headless+ requires an image or disk folder.
Direct source launches and image wrapping are developer workflows; they do not
change the fixed BIOS boot rule or add compatibility for old image formats.

For an ordered first-run path, see
link:getting_started.adoc[Getting Started]. The machine and image contract is
defined in link:sc16_architecture.adoc[SC-16 architecture].

== Manifest version 1

[source,json]
----
{
  "version": 1,
  "slug": "sample",
  "name": "Sample",
  "install_disk": "sample-disk",
  "capacity_bytes": 67108864,
  "boot": {
    "source": "src/main.c",
    "output": "main.bin"
  },
  "assets": null,
  "executables": []
}
----

The slug must match the directory name. +install_disk+ is optional; when
omitted, the slug is used. It must be a valid, unique disk ID and cannot
conflict with another package's slug or legacy disk ID. Program slugs use
lowercase ASCII letters, digits, and hyphens; they begin with a letter/digit
and do not end in a hyphen. Disk IDs allow 1-32 ASCII letters/digits,
underscores, and hyphens; Windows device names and case-insensitive collisions
are rejected.
Human display names are separate from IDs.

The boot output is +main.bin+ for USER mode or +kernel.bin+ for KERNEL mode.
For embedded C user code in an assembly kernel, specify +embedded_c+ beside
+source+, as SisuOS does. Additional +executables+ entries specify +source+,
+output+, and optionally an integer relocation +base+. Sources, seed paths,
and output names are validated; directory traversal and symlinks are rejected.
+assets+ may be +null+. Otherwise, every regular file in its declared directory
tree is included at that relative path in the built and installed disk. Put
runtime data in this tree; source, documentation, and build tools are not
copied unless explicitly declared as runtime assets. Each executable is
installed as a protected file.

== Safe updates

Installation stages and validates the entire resulting disk before switching
directories. Existing disk identity, label, capacity, read-only status, protected
paths, and unrelated writable files are preserved. A read-only disk cannot be
updated. New executables are added to the existing protected-file list.
Disk capacity checks include installed files and package ownership metadata.

The installer records package-owned file fingerprints in +.sc16-owned.json+.
It updates unchanged owned files, removes unchanged retired owned files, and
rejects modified owned files or conflicting new seed paths rather than
overwriting them. Fingerprints are length plus FNV-1a, for update bookkeeping,
not cryptographic authenticity. On first adoption, seeds must match the
shipped bytes; known executable outputs may be replaced. Other local files
are never adopted implicitly. Back up or move a conflicting local file before
retrying an intentional update.

An install journal and backup directory support interruption recovery. Retry
the same install command to restore an interrupted switch or finish cleanup.
An interrupted build may leave +build/programs/.stage-<slug>/+; inspect and
remove that generated staging directory before rebuilding. Errors retain
explicit diagnostics. Windows sharing/access errors receive a bounded retry
only in offline tooling; CPU instruction execution is unchanged.
Do not run build/install/migration commands concurrently with one another or
while an emulator is using the affected disks.

== Migrating existing disks

[source,powershell]
----
cargo run --bin sc16build -- migrate-program-disks --dry-run
cargo run --bin sc16build -- migrate-program-disks --apply
----

The explicit +legacy_disk+ mapping renames +APP00001+ through +APP00017+
and +SisuOS-1+ to each package's configured +install_disk+ (or slug). It also
updates manifest IDs and the preferred disk in +config/bios.json+, preserving
other settings and disk contents. +DISK0001+ and +DISK0002+ are data disks and
stay unchanged.
Both old and new paths existing is an error: migration never merges them.
Dry-run changes nothing. Apply creates a migration journal; rerun apply to
resume after an interrupted rename. No aliases are installed for obsolete
source folders, disk IDs, or module build commands.
