= SC-16 Folder-Backed Disk Format
:toc: left
:toclevels: 2

== Manifest version 1

Each folder-backed disk contains a UTF-8 +disk.json+ manifest at its root.
Version 1 has this form:

[source,json]
----
{
  "version": 1,
  "id": "DISK0001",
  "label": "System",
  "capacity_bytes": 67108864,
  "read_only": false,
  "protected_files": ["kernel.bin", "system/config.dat"]
}
----

The manifest root must be an object. All fields except +protected_files+ are
required. Unknown fields and unsupported versions are errors; adding fields
requires a new manifest version.

[cols="1,1,3"]
|===
|Field |Type |Contract

|+version+
|Unsigned integer
|Must equal +1+.

|+id+
|String
|Exactly eight ASCII letters, digits, +_+, or +-+. Disk discovery must require
that it matches the containing disk directory's identity.

|+label+
|String
|One to 64 Unicode scalar values, non-whitespace, and containing no control
characters.

|+capacity_bytes+
|Positive unsigned 64-bit integer
|Hard maximum for disk usage. Usage is the sum of regular-file content lengths;
metadata and directory entries do not count. Writes and file growth must not
exceed this limit.

|+read_only+
|Boolean
|When true, all guest mutations to the disk are denied.

|+protected_files+
|Array of strings
|Optional; defaults to empty. Entries are unique normalized guest-relative
file paths. Protected files cannot be written, replaced, deleted, or renamed.
|===

A protected-file path is at most 128 ASCII bytes, uses +/+ as its only
separator, and has one or more segments containing only ASCII letters, digits,
+_+, +.+, or +-+. Empty, +.+, +..+, absolute, backslash-containing, and
otherwise invalid paths are rejected. The mounted filesystem must resolve paths
beneath the disk root and reject unsupported host-file types and host I/O
failures.

== Boot selection

The manifest never selects an executable or its privilege mode. The
BIOS applies a fixed rule to regular files at the selected disk root:

* If exactly +kernel.bin+ exists, load it in kernel mode.
* If exactly +main.bin+ exists, load it in user mode.
* If both or neither exist, report +NOT_BOOT+.

A selected +kernel.bin+ is trusted kernel code. This rule is not secure boot and
does not authenticate the disk or image. Disk metadata and user programs cannot
override executable selection or mode.

The common +bios.bin+ image is always counted as trusted firmware and runs in
kernel (Supervisor) mode. This is a fixed emulator policy, not a signature check:
the image is not authenticated, and the trust assumption does not imply secure
boot.

Boot executables use the version 2 +SC16IMG2+ container specified in
link:sc16_architecture.adoc[+sc16_architecture.adoc+]. The loader rejects the
previous +SC16IMG1+ format; disks containing v1 images must be rebuilt with
+sc16build+ or otherwise migrated. Segment permissions and alignment are
validated as image metadata. The MMU enforces mapped permissions when
translation is enabled; normal BIOS USER boot does not yet enable translation
and is not an isolation boundary.

Without an explicit program path, the guest BIOS discovers ID-named folder
directories under +disks/+ in stable order. It presents the disk, automatic
startup, and SC-NET node ID as selectable settings. Up/Down changes the
selection, Left/Right changes the selected option, and Enter edits a setting
or boots the selected disk. Escape cancels an edit.
+--disk ID+ preselects a boot disk without bypassing checks. Metadata is
validated only when a disk is selected, so an invalid manifest cannot hide
other boot choices. Invalid metadata, images, and +NOT_BOOT+ cases are logged
to the Bug Monitor and leave the selector available for another choice. Reset
restarts firmware and rescans the collection. The BIOS service loads the
SC-16 image container directly, preserving its entry point, segment
permissions, and alignment, and never compiles or assembles guest source.
KERNEL maps to the CPU's +Supervisor+ privilege mode; USER maps to +User+.

The common +bios.bin+ image is required, trusted by policy, and executes in
kernel (Supervisor) mode before disk selection.
The guest BIOS renders through the character-cell display and uses the
supervisor-only firmware service at +0x43400+ for disk discovery and image
loading. This service is a firmware boundary, not a general syscall or
authenticated boot mechanism. The guest folder-filesystem service is exposed
through the separate register gateway below; it does not use the retired
block-disk API. Explicit source or flat-binary launches retain their developer
workflow and can mount a folder disk with +--disk ID+.

== Guest BIOS disk service

The service is invoked by writing a command byte to +0x43400+ while in
Supervisor mode. All multi-byte values are big-endian.

[cols="1,2,3"]
|===
|Command |Operation |Request and result

|+1+
|Count disks
|Writes the default selection index to +0x43402+ and the candidate count to
  +0x43404+. +--disk ID+ selects the initial index when it matches a
  discovered ID; otherwise index zero is used and the missing ID is logged.
  +0x43406+ is nonzero when automatic startup is enabled and a preferred disk
  was found. With that value set, the BIOS waits five seconds for Space before
  booting; the startup wait marker at +0x4342e+ is nonzero during this window.
  The SC-NET node ID is written at +0x43410+ in a 17-byte
  NUL-terminated buffer (maximum 16 printable ASCII bytes). The number of
  custom settings is at +0x4340e+.

|+2+
|Read disk ID
|The 16-bit candidate index is at +0x43402+. Output pointer and capacity are
  at +0x43406+ and +0x4340a+. The selected ID is written as ASCII followed by
  NUL.

|+3+
|Boot disk
|The candidate index is at +0x43402+. The service validates the folder
  manifest and boot image, loads the fixed +main.bin+ or +kernel.bin+ image,
  mounts the selected folder, and transfers control in the corresponding
  privilege mode.

|+4+
|Save BIOS settings
|The selected disk index is at +0x43402+, startup behavior at +0x43406+
  (+0+ selector, +1+ boot preferred disk), and the NUL-terminated SC-NET node
  ID at +0x43410+ in a 17-byte NUL-terminated buffer (maximum 16 printable
  ASCII bytes). Saves the settings to the emulator-root +bios.json+, preserving
  additional boolean, integer, and string settings.

|+5+
|Reload BIOS settings
|Reloads +bios.json+ and returns the selected disk index, disk count, startup
  behavior, and SC-NET node ID in the same fields as command +1+.

|+6+
|Read custom setting
|The zero-based index in the sorted settings list is at +0x43402+. The result
  record starts at +0x43430+: a 17-byte NUL-terminated name, a type byte
  (+0+ boolean, +1+ string, +2+ integer), and a 24-byte NUL-terminated value.
  Boolean values are +Yes+/+No+ and integer values use signed decimal text.

|+7+
|Write custom setting
|Writes the same record layout returned by command +6+. The name and type
  must match an existing setting. String values are limited to 16 printable
  ASCII bytes; integer values must parse as signed 64-bit decimal values.
|===

Status at +0x4340c+ is zero on success and one on failure. Failures are also
logged to the Bug Monitor; a failed boot leaves the BIOS available to retry.
The BIOS menu uses F9 to reload settings and F10 to save. During automatic
startup, press Space within five seconds to enter BIOS setup. The emulator uses
F1 to pause/resume, F2 for the Bug Monitor, F3 to reset, F4 to reboot, and F5
to stop. The SC-NET node ID identifies the emulator on SC-NET and is
independent of guest application network titles.

The root settings file has this versioned shape:

[source,json]
----
{
  "version": 1,
  "preferred_disk": "APP00001",
  "startup_behavior": "selector",
  "network_name": "SC16-0123456789A",
  "settings": {
    "example_enabled": true,
    "example_integer": 42,
    "example_string": "value"
  }
}
----

Up to eight additional setting values are JSON booleans (Yes/No), signed
integers, or printable ASCII strings of at most 16 bytes. Example values are
+true+, +42+, and +"value"+. These appear in the BIOS settings list and can be
edited there; changes are saved only with F10.

+preferred_disk+ may be +null+ when no disk is selected. Startup behavior is
+selector+ or +boot_preferred+. +network_name+ is a 1-16 character printable
ASCII SC-NET node ID. When omitted, the BIOS generates an ID in the
+SC16-+ plus 11 hexadecimal digit form. Missing +bios.json+ uses these
defaults; invalid JSON or unsupported field types are reported rather than
silently replaced.

== Guest folder-filesystem service

Booting a folder disk mounts that disk for the guest. The current compatibility
service is selected by writing one command to +0x43100+ while in USER mode.
Path and buffer addresses are big-endian 32-bit values; paths are null
terminated ASCII, at most 128 bytes, and use the normalized relative-path
syntax above. Guest buffer ranges must fit in configured memory and must not
overlap memory-mapped devices. Transfers are limited to 4096 bytes. Service
failure sets status at +0x43110+ to 1 and writes the diagnostic to the Bug
Monitor; success sets status to 0.

[cols="1,2,3"]
|===
|Command |Operation |Request and result

|+0x41+
|List directory entry
|+0x43116+ points to a directory path; an empty string selects the disk root.
  The 16-bit entry index is at +0x4310a+. The output pointer and capacity are
  at +0x4311a+ and +0x4311e+. An entry encodes name plus NUL, a type byte
  (+1+ for directory, +0+ for file), and a 32-bit big-endian size. Result at
  +0x4310e+ is the total entry count; an index past the end returns an empty
  name.

|+0x42+
|Read file
|Path pointer at +0x43116+, 32-bit file offset at +0x43112+, output pointer
  at +0x4311a+, and requested length at +0x4311e+. Result is bytes read;
  32-bit file size is returned at +0x43120+.

|+0x43+
|Replace file
|Path and input buffer pointers at +0x43116+ and +0x4311a+; input length at
  +0x4311e+. The operation replaces the whole file and returns bytes written.

|+0x44+
|Create directory
|Path pointer at +0x43116+.

|+0x45+
|Delete file or empty directory
|Path pointer at +0x43116+.

|+0x46+
|Rename file or directory
|Source path pointer at +0x43116+; destination path pointer at +0x43112+.

|+0x47+
|Query entry metadata
|Path pointer at +0x43116+; output pointer at +0x4311a+. Output is a type
  byte (+1+ for directory, +0+ for file) followed by 32-bit big-endian size.
|===

The 16-bit result register is at +0x4310e+ and status is at +0x43110+.
Guest mutations obey disk-wide read-only mode and manifest protected paths.
Guest code cannot create, replace, remove, or rename the root boot filenames
+main.bin+ and +kernel.bin+. This narrow register gateway is not the finalized
general syscall ABI and does not provide general MMIO or process isolation.
Command +0x80+ remains as a read-only recursive file-list compatibility shim
for +lib/disk.h+; legacy block commands are rejected.

== Implementation status

The Rust parser validates version 1 disk-manifest fields and protected paths.
`FolderDisk` validates and opens individual folders, discovers ID-named disks, lists and
reads regular files, lists directories, creates directories, writes, copies,
renames, and deletes files and empty directories, accounts regular-file bytes,
enforces disk-wide read-only mode, protected paths, and write/copy capacity,
rejects over-capacity disks at mount, and selects/validates the fixed-name boot
image. Image parsing accepts only `SC16IMG2`, checks segment ranges, overlap,
alignment, permissions, entry-point execution permission, reserved fields, and
exact file length. `sc16build import-block-disk` exports legacy JSON blocks as
regular files without modifying the source. `sc16build package-disk` builds
one program into a new boot-disk folder with `main.bin` or `kernel.bin`.
Guest integration includes a bounded user-mode register gateway for directory
listing, reads, writes, directory creation, deletion, rename, and metadata.
All 17 runnable applications and their local assets have validated folder
packages. DiskEditor is a USER-mode folder-file editor, and guest block-level
disk commands and the emulator's block device are removed. Original JSON
images remain only as import inputs. Folder-disk BIOS discovery, selection,
image validation, common firmware startup, and launch-mode transfer are
implemented in the runtime; the final guest-resident BIOS and selector remain
open architecture work.
