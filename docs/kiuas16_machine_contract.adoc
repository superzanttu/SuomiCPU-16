= Kiuas16 RV64 Machine Contract
:toc: left
:toclevels: 2

== Status

This document defines the selected Kiuas16 machine contract for the planned
RV64 target and records implementation status for partial components. The
Rust module has initial integer/privileged execution, translation, ROM/RAM
bus, PLIC, and UART slices, but does not yet satisfy the full RV64GC, BIOS, or
xv6 compatibility requirements. The existing emulator continues to implement
the separate SC-16 contract in
link:sc16_architecture.adoc[SC-16 Machine Architecture].
The guest language profiles, object layout, and procedure ABI are defined in
link:kiuas16_guest_abi.adoc[Kiuas16 Guest ABI and Language Profiles].

The initial configuration is fixed for xv6 bring-up: one hart, 128 MiB of
RAM, and the pinned xv6-riscv revision
+e93dabeb98431235c6e1a101cb96c73c923fdbc4+. Extending the configuration
requires explicit compatibility tests; it must not change this baseline
silently.

== Processor and execution environment

The target contract requires RV64GC: RV64I, M, A, F, D, C, Zicsr, and
Zifencei, with XLEN 64. Instructions and data are little-endian. Instruction
alignment is two bytes. The base integer register file has x0 through x31; x0
always reads zero and discards writes. F and D registers and their
architectural status state are required. All arithmetic wraps as specified by
RISC-V; address arithmetic does not wrap at a narrower legacy SC-16 width.

The target privileged execution environment has Machine, Supervisor, and User
modes. It must implement the CSR, trap, interrupt, delegation, counter, and
return behavior required by xv6 and the privileged architecture. At minimum it
requires PMP, Sv39, supervisor timer compare (Sstc), and hardware page-table
accessed/dirty-bit updates enabled by +menvcfg.ADUE+. Hypervisor and vector
extensions are not part of this target.

The current implementation is a subset, not RV64GC: its capability profile
reports I/M/A/C, Zicsr, and Zifencei, and explicitly lists F and D as
unsupported. Required privileged features in that profile describe the
xv6-target requirement and do not claim complete architectural conformance.

Unsupported instruction encodings, privilege operations, CSR accesses, and
translation modes trap or read back architecturally defined WARL values; they
must never be treated as successful no-ops when software can observe the
difference. +misa+ reports MXL and the implemented single-letter extensions;
Zicsr and Zifencei are guaranteed by this contract independently of +misa+.
The initial board has one hart, with +mhartid+ equal to zero; hart IDs are
stable and are not reused.

=== Privileged features required by xv6

* +satp+ supports Bare and Sv39. Sv39 uses 4 KiB pages, three levels, and
  512 64-bit PTEs per page-table page. Noncanonical virtual addresses fault.
* PMP implements the NAPOT matching and permissions needed by the pinned
  kernel. Its sequence writing +0x3fffffffffffff+ to +pmpaddr0+ and +0x0f+
  to +pmpcfg0+ allows S/U accesses to the physical address range; PMP checks
  still do not make unmapped physical addresses valid.
* +menvcfg.ADUE+, when set by M-mode, enables hardware setting of Sv39 PTE
  accessed and dirty bits. When clear, access to a PTE requiring an unset bit
  raises the architecturally required page fault. Updates are atomic with
  respect to competing page-table accesses.
* Sstc provides +stimecmp+ at CSR +0x14d+. M-mode controls S-mode access with
  +menvcfg.STCE+; +mcounteren.TIME+ controls S-mode reads of +time+. A timer
  interrupt is pending exactly when the time comparison and interrupt-enable
  conditions require it, and is delivered through the delegated supervisor
  timer interrupt path.
* Atomic memory operations are coherent between harts. The initial one-hart
  configuration still implements the architectural A extension and ordering
  semantics; it does not emulate atomic operations as ordinary, reorderable
  loads and stores.
* +fence+, +fence.i+, and +sfence.vma+ have the required ordering and
  translation/instruction-cache effects. No guest-visible cache may retain
  stale instructions or translations across the corresponding fences.

== Physical address space

Physical addresses are unsigned 56-bit values, matching the maximum address
width expressible by Sv39 PPNs and a 4 KiB page offset. The bus preserves every
implemented physical-address bit. It never wraps, masks to 30 bits, aliases
unmapped space into RAM, or uses host allocation size as a substitute for the
guest map.

The following half-open ranges define the initial board. Undefined portions
of each device's register interface remain governed by the
link:kiuas16_device_contract.adoc[device contract]; an address inside an
aperture is not by itself a valid register access.

[cols="1,1,2,2",options="header"]
|===
|Physical range |Size |Owner |Behavior
|+0x00000000..0x00001000+ |4 KiB |Lauteet |Unmapped; access fault
|+0x00001000..0x00010000+ |60 KiB |Sytyke |Read/execute boot ROM; writes fault
|+0x00010000..0x0c000000+ |Reserved |Lauteet |Unmapped; access fault
|+0x0c000000..0x10000000+ |64 MiB |Vihta |PLIC aperture; see device contract
|+0x10000000..0x10001000+ |4 KiB |Höyry |16550-compatible UART; see device contract
|+0x10001000..0x10002000+ |4 KiB |Kiulu |Reserved Virtio-MMIO v2 root block aperture; model not implemented
|+0x10002000..0x80000000+ |Reserved |Lauteet |Unmapped; access fault
|+0x80000000..0x88000000+ |128 MiB |Löyly |RAM; usable and DMA-addressable
|+0x88000000..0x0100000000000000+ |Reserved |Lauteet |Unmapped; access fault
|===

The PLIC aperture follows the pinned +qemu -machine virt+ physical layout.
Only implemented registers and contexts are accessible; the full aperture is
not backing RAM. Register access, IRQ assignments, protocol identities,
reset, and unimplemented-device outcomes are defined in
link:kiuas16_device_contract.adoc[the device contract]. The root controller
remains at +0x10001000+ with the identity expected by upstream xv6; no
additional boot-volume controller may displace it.

RAM is contiguous from +0x80000000+ through +0x87ffffff+. The initial firmware
loads the kernel ELF into that RAM; kernel allocation and all DMA are bounded
by the same configured RAM limit. Reads, writes, fetches, page-table walks, and
DMA outside a mapped range fail explicitly. A transfer crossing a region
boundary is checked as a whole and cannot partially modify memory or a device.
RAM may be smaller only in isolated tests that declare their non-xv6 purpose;
it may not be smaller in the xv6 acceptance configuration.

== Reset and firmware entry

A cold machine reset has the following defined state:

* Privilege is M-mode, PC is +0x00001000+, and +mhartid+ is zero.
* Integer and floating-point registers are zero; x0 remains hardwired to zero.
  The ROM establishes its own stack before using one.
* Software-writable architectural CSRs start at zero, subject to their
  specified WARL masks and read-only identity fields. In particular,
  +mstatus+, +mie+, +medeleg+, +mideleg+, +mtvec+, +mepc+, +mcause+,
  +mtval+, +stvec+, +sepc+, +scause+, +stval+, +satp+, +pmpcfg0+, and
  +pmpaddr0+ are zero. +satp+ is Bare, traps are delegated nowhere, and PMP
  starts disabled.
* +mip+ device-pending sources start clear. +stimecmp+ starts at
  +0xffffffffffffffff+, so the Sstc timer is not pending at reset.
* +fcsr+ is zero and floating-point status is Off.
* +menvcfg+ and +mcounteren+ are zero. Firmware must explicitly enable ADUE,
  Sstc, and the +time+ counter before relying on them from S-mode.
* +mcycle+, +minstret+, and the virtual +time+ counter start at zero.
* A machine reset reinitializes the core and volatile device/controller state,
  including the UART and PLIC. Boot ROM and guest RAM contents are preserved;
  reset does not initialize guest RAM.

+Kiuas16Machine::reset()+ implements this reset policy. Its
+profile()+ reports the fixed board capabilities and the instance's configured
RAM range, which may be smaller than the xv6 profile only for isolated tests.

The Sytyke ROM is immutable to guest stores and executable at reset. Fetches
from unmapped physical addresses and stores to ROM fault. BIOS implementation,
ROM image format, recovery behavior, and the exact M-to-S handoff protocol are
specified by the separate BIOS tasks; they are not inferred from this memory
map.

For upstream xv6 handoff, the firmware loads the kernel at its ELF physical
addresses beginning at +0x80000000+, starts the kernel entry in M-mode, and
preserves hart identity in +mhartid+. xv6's entry code establishes its stack,
then its +start()+ configures PMP, delegation, Sv39, ADUE, and Sstc before
returning to S-mode. The firmware must not enter the kernel directly in
S-mode or enable paging before the kernel performs this setup. No device-tree
pointer is required by this pinned kernel's entry path.

== Address translation, access faults, and ordering

Instruction fetches, loads, and stores use 64-bit virtual addresses. With
+satp.MODE=Sv39+, the MMU checks canonicality and each PTE's validity,
permissions, privilege, and accessed/dirty state. A page fault reports the
faulting virtual address and the correct instruction/load/store page-fault
cause. With Bare mode, the virtual address is used as the physical address,
then checked against the physical map and PMP.

Misaligned instruction targets and misaligned data accesses raise their
architectural misaligned exceptions; a misaligned store has no partial
effects. An access to an unmapped physical address raises the corresponding
instruction/load/store access fault. +mtval+/+stval+ contains the faulting
effective address for address-related faults; trap cause and privilege follow
the architectural delegation and priority rules. Device access-width,
alignment, side-effect, and interrupt behavior is specified per device.
Invalid device accesses must not be completed as zero-valued reads or ignored
writes.

The core exposes a diagnostic single-step operation that returns synchronous
traps to its caller, and a trap-delivering single-step operation that captures
the architectural state and enters the selected handler. The trap-delivering
path also checks pending, enabled interrupts before executing the next
instruction, applies delegation and privilege-level interrupt enables, and
supports direct or vectored interrupt entry. Its WFI state suspends stepping
until an interrupt becomes pending. A faulting instruction or delivered
interrupt increments +mcycle+ but not +minstret+. Machine integration must use
the trap-delivering path; device-driven pending lines and the virtual timer
remain separate requirements.

+Kiuas16Machine+ now owns a cold-reset core and physical bus and exposes
deterministic single-step execution through that trap-delivering path. Each
step polls the bus PLIC, advances the core's virtual time, and executes or
delivers the pending trap/interrupt. The machine also exposes the core and bus
for observation or device setup, plus headless UART input/output methods.
This is a headless integration surface, not a complete host runtime or BIOS.

[[headless-runner]]
=== Bounded headless host runner

The Rust +kiuas16::runtime::run_headless()+ adapter and separate
+kiuas16-run+ binary execute this same machine stepping path without a
graphics context or the legacy SC-16 runtime. They do not interpret guest
syscalls, construct processes, generate a shell prompt, load an ELF directly,
or initialize guest queues. Execution always starts at the protected ROM
reset vector with the standard one-hart/128 MiB board.

[source,powershell]
----
cargo run --bin kiuas16-run -- --rom C:\path\kiuas16-rom.bin --steps 1000000 --root C:\path\root.raw --serial-input C:\path\serial.bin
----

The caller supplies a raw ROM of exactly +BOOT_ROM_BYTES+ (61440 bytes),
mapped at +0x1000+. This is not the legacy SC-16 +firmware/bios.bin+ format.
The runner does not build or supply Sytyke firmware. +--steps+ is a required,
nonzero 64-bit budget of attempted/idle machine cycles; virtual time advances
without consulting host wall time. Budget exhaustion is reported explicitly,
not interpreted as boot completion or guest shutdown.

Only +--root+ attaches a disk. It opens an existing nonempty, 512-byte-aligned
raw image read-only by default. +--root-writable+ is an explicit opt-in and
requires +--root+; use disposable copies for writable experiments. The
runner never creates, formats, guesses, or rewrites an image at startup.
Guest requests can access only sectors of that explicitly opened media.
Successful guest writes follow the negotiated Kiulu durability rules;
stopping at the cycle budget does not synthesize a guest flush or shutdown.
Dropping the machine closes its media handles.

+--serial-input+ supplies binary bytes from a file, queued in order only
when the UART has room. This host-side backpressure avoids overflowing the
hardware FIFO; it does not simulate baud timing or terminal key events.
The report counts bytes accepted into the FIFO, not bytes consumed by guest
software. Unaccepted input at budget exhaustion is an explicit CLI error.
Only guest UART output goes to stdout, including binary bytes. Host
diagnostics, cycle/outcome counts, final PC/time, and the most recent
synchronous trap go to stderr.

Guest traps are delivered to guest handlers normally, including ECALL;
their presence alone is not an OS-level failure. +--deny-traps+ makes any
synchronous trap a CLI error after the bounded run, for strict exception-free
fixtures. Media backend errors, unhandled core errors, serial output/flush
failures, invalid inputs, and attachment failures are explicit errors.
A successful command means the requested bounded run completed under these
rules, never that a BIOS, kernel, shell, or acceptance workload succeeded.
Callers must assert the required guest output and state independently.

The integration tests in +tests/kiuas16_runtime.rs+ execute ROM instructions
that negotiate modern Virtio, construct RAM descriptor/ring metadata, perform
raw-sector reads/writes/flushes, acknowledge interrupts, and reset the device.
A separate fixture loads an executable sector through Kiulu DMA, jumps to
that RAM payload in M-mode, reads +mhartid+, resets the firmware-used
controller, and performs a new read using fresh device state. This is a
fixed-encoding hardware/handoff fixture, not Rust-compiled Sytyke, an ELF
loader, a specified boot volume, or the pinned xv6 kernel.

[[rom-assembler]]
=== Initial Rust-native ROM assembler

+kiuas16-asm+ and +assembler::rv64::assemble_boot_rom()+ assemble a
single source unit directly into the 61440-byte raw ROM accepted by the
runner. Source starts at +0x1000+; remaining ROM bytes are zero-filled.
No external assembler or linker is invoked. The existing +sc16asm+ command
and legacy SC-16 image format are unchanged.

[source,powershell]
----
cargo run --bin kiuas16-asm -- .\tests\fixtures\kiuas16_storage.S C:\path\storage-rom.bin
cargo run --bin kiuas16-run -- --rom C:\path\storage-rom.bin --root C:\path\disposable.raw --steps 300 --deny-traps
cargo test --test kiuas16_assembler -j 1 -- --test-threads=1
----

The storage fixture needs at least two sectors and reads sector 1. Its binary
UART output is +4b 52 00 01 00 01 03 00+ when that sector contains +R+ bytes
and media is read-only. Adding +--root-writable+ changes the fourth output
byte to zero and persists +W+ as the first byte of sector 1; the remaining
sector bytes are retained. The guest negotiates modern Virtio including
flush, builds RAM queues, reads/writes/flushes, observes completion/IRQ state,
acknowledges the IRQ, and resets the controller. Nested calls save/restore
+ra+ on a 16-byte-aligned RAM stack. The integration test creates disposable
media, checks both exact output variants and persisted disk bytes, and never
uses a user disk.

Supported syntax is intentionally limited:

* Lowercase RV64 integer register names +x0..x31+ and standard ABI aliases,
  including +fp+; comma-separated operands and +offset(register)+ memory.
* +lui+, +auipc+, integer immediate arithmetic/logical/comparison/shift
  instructions, base register arithmetic/logical/comparison/shift instructions,
  +addw/subw+, integer loads/stores, all six base
  conditional branches, +jal rd,target+, and +jalr rd,offset(base)+.
* All RV64M operations: +mul/mulh/mulhsu/mulhu/div/divu/rem/remu+ and
  +mulw/divw/divuw/remw/remuw+, each with three integer register operands.
  High products select bits 127:64 of signed/signed, signed/unsigned,
  or unsigned/unsigned products respectively. Word operations use the low
  32 input bits and sign-extend their 32-bit result to XLEN, including
  unsigned division/remainder. Architectural zero-divisor and signed
  overflow results do not trap. This exposes existing CPU semantics without
  adding C 128-bit types or new compiler operator lowering.
* +nop+, +mv+, +ret+, +j+, +call+, +li+, and +la+.
  +li+ accepts signed 32-bit constants and emits +lui/addiw+.
  +la+ emits checked local PC-relative +auipc/addi+.
  +call+ is a checked local +jal+, not a long-call relocation.
* Zero-test branch aliases +beqz/bnez/blez/bgez/bltz/bgtz rs,target+ and
  reversed-comparison aliases +bgt/ble/bgtu/bleu rs,rt,target+. Each emits
  one four-byte base branch with zero or swapped register operands.
  Signed +blez/bgez/bltz/bgtz/bgt/ble+ comparisons use XLEN, not a word
  truncation; +bgtu/bleu+ compare unsigned XLEN values. Targets accept the
  same named/numeric local labels or byte displacements as base branches.
  Existing four-byte alignment and signed 13-bit displacement checks apply;
  no long-branch relaxation, extra scratch register, or compressed form is added.
* +wfi+, +ecall+, +ebreak+, +mret+, +sret+, +fence+, and +fence.i+
  with no operands. Explicit fence predecessor/successor lists are unsupported.
* +csrrw/csrrs/csrrc+ and +csrrwi/csrrsi/csrrci+, plus
  +csrr/csrw/csrs/csrc/csrwi/csrsi/csrci+ pseudos. CSR addresses accept
  unsigned 12-bit numbers or the architectural names implemented by the
  machine (supervisor/machine status, interrupt, trap, scratch, delegation,
  counter, PMP, SATP, environment, hart ID, and supervisor timer compare).
  Immediate sources are unsigned five-bit numbers; register sources require
  integer registers. The assembler encodes numeric CSR addresses even if the
  machine does not implement them; privilege, read-only, and implemented-CSR
  checks remain CPU execution semantics.
* +lr.w/lr.d+, +sc.w/sc.d+, +amoswap.w/amoswap.d+, +amoadd.w/amoadd.d+,
  +amoand.w/amoand.d+, +amoor.w/amoor.d+, +amoxor.w/amoxor.d+,
  +amomin.w/amomin.d+, +amomax.w/amomax.d+, +amominu.w/amominu.d+, and
  +amomaxu.w/amomaxu.d+, optionally suffixed with
  +.aq+, +.rl+, or +.aqrl+. Atomic address operands require zero offset,
  written as +(register)+ or +0(register)+. LR takes a destination and address;
  SC/AMOs take a destination, source register, and address. SC returns zero
  on success and nonzero on reservation failure; either attempt consumes the
  reservation. Word LR/AMO results sign-extend to XLEN; SC returns status,
  not the old value. Min/max compare signed or unsigned values at the selected
  width. This covers the RV64A instruction set, not newer atomic extensions.
  RAM-only access, reservation invalidation, and address/permission faults
  remain CPU/machine semantics; suffix encoding does not add multi-hart support.
* Named labels and reusable decimal numeric local labels (+1:+, +12:+).
  Directional references (+1b+, +1f+) select the nearest preceding/following
  definition in source order, including a preceding label on the same line.
  Leading zeros do not change the decimal label number. Numeric labels have
  source-unit scope, may repeat, and cannot be exported with +.globl/.global+.
  Branches, jumps/calls, +la+, and label data operands accept these references;
  bare numbers remain constants/displacements, not numeric-label references.
  Branch/jump numbers are byte displacements
  from the instruction PC. Instructions and direct branch/jump targets must
  be four-byte aligned; compressed instructions are not supported.
* +.text+, +.globl/.global+, +.byte+, +.word+ (32 bits), +.dword+ (64 bits),
  +.zero+, and power-of-two +.balign+. Data is little-endian; label data
  operands resolve to absolute ROM addresses. Global declarations require a
  definition, but do not select an entry point or export an object symbol.
  Numeric operands reuse the shared assembler's integer-literal parser.
* +#+ comments. Preprocessor directives, expressions (including label arithmetic),
  other sections/directives, F/D/C instructions, external
  symbols, relocatable objects, and ELF output are not supported.

Malformed input, unknown operations, unresolved/duplicate labels, immediate
and ROM overflow, and misaligned instructions diagnose with source line
numbers. The CLI assembles successfully before touching the destination and
rejects overwriting the source path. These source-built assembly fixtures
advance the toolchain path, but do not provide compiled-C, independent LP64D
call certification, Sytyke, or xv6 acceptance.

bytes in sector 1, its exact binary UART output is
+43 00 52 01 00 01 03 00+ for read-only media. Adding +--root-writable+
changes the fourth byte to zero and persists +W+ as the first byte of sector 1.
The host neither initializes queues nor performs guest operations on its behalf.
Descriptor flags/next links, available entries/index, and the used index use
typed volatile +unsigned short+ accesses with two-byte strides. The guest
explicitly publishes each ring entry before its index. Poisoned descriptor
and available-ring tests check exact fields and untouched neighboring bytes,
plus trap-free execution, restored registers, and persisted disk contents.
After reading, a generic +void *+ byte-copy helper transfers 16 sector bytes
into an automatic buffer, changes its first byte to +W+, and copies the prefix
back before writing. Two doublewords at +0x80000700+ report the snapshot and
DMA destination addresses; tests inspect both buffers and the complete sector.
The helper is compiled guest code, not a host memory-copy service.
File-scope +u8/u16/u32/u64+ and +buffer+ typedefs express the guest's field
widths and copy interface; their resolved types use the same code generation
as the underlying declarations.
Anonymous file-scope enums name driver states, descriptor flags, request
types, queue/sector sizes, and the MMIO base. Constants use RV64 LP64 evaluation
and do not allocate RAM objects.
The guest's +request+ helper uses +switch+ to select read/write/flush descriptor
updates; unknown requests return without touching the request header or queue.
The same source retains the exact UART, descriptor/ring bytes, and disk results.
Private MMIO and request helpers now use file-scope +static+ linkage.
An initialized-by-startup RAM lock protects request submission with acquire
exchange and release store, including unlocking on unknown requests.
An acquire load checks the lock is released after the read/write/flush sequence.
Successful and unknown requests jump to shared +unlock+ cleanup; lock
contention returns before taking ownership and does not unlock another caller.

The initial language/backend subset is deliberately bounded:

* C99 +_Bool+, signed/unsigned 16-bit +short+, 32-bit +int+, and 64-bit +long+,
  distinct +char/signed char/unsigned char+, +void+ returns, and pointers to those integer types,
  either unqualified or volatile-qualified.
  Dereferences use byte, halfword, word, or doubleword accesses respectively.
  Decimal, octal, and hexadecimal literals cover the full unsigned 64-bit
  range, with optional +U+, +L+, +UL+, or +LU+ suffixes (case insensitive).
  LP64 C90 candidate types determine the first representable type:
  unsuffixed decimal uses +int/long/unsigned long+; octal/hexadecimal also
  try +unsigned int+ before +long+. The +U+ suffix tries +unsigned int+ then
  +unsigned long+, +L+ tries +long+ then +unsigned long+, and +UL/LU+ selects
  +unsigned long+. Literal typing is target-specific; the legacy SC-16
  literal parser and its limits are unchanged. Unary minus supplies negative
  expressions. Overflow, invalid digits/suffixes, +long long+,
  other scalar types, and floating point diagnose.
  Plain +char+ is unsigned, matching the shared Kiuas16 ABI contract;
  +signed char+ narrows/sign-extends at eight bits. All character types promote
  to +int+ and remain distinct for pointer compatibility.
  Both +short+ types also promote to +int+; unsigned halfwords therefore
  participate in signed 32-bit arithmetic until wider conversions apply.
  Short conversions retain the low 16 bits; signed halfwords sign-extend and
  unsigned halfwords zero-extend in values and integer register/stack calls.
  Matching halfword pointer arithmetic scales by two bytes. Qualified pointees
  and const/volatile integer objects are supported.
* +_Bool+ occupies one byte, matching the shared target ABI layout.
  Integer and pointer conversions yield zero for zero/null and one for every
  nonzero value/address, testing the full source width before normalization.
  Boolean values promote to signed +int+ for arithmetic, shifts, comparisons,
  and switch dispatch. Casts, initialization, assignment, parameters, and
  returns use the same normalization; register/stack call values are zero or
  one in XLEN. Globals and automatic arrays accept integer constant/list/
  designated initializers with zero-filled omissions, and aliases preserve
  the boolean type. +sizeof(_Bool)+ is one and boolean array strides are one;
  arrays still use the existing eight-byte object/frame alignment rules.
  Ordinary/const/volatile boolean pointers, pointer tables, two-level cursors,
  generic void-pointer conversions, and null constants reuse the existing
  pointer rules. Dereferences use byte accesses; boolean updates perform
  promoted integer arithmetic followed by conversion back to zero/one.
  Byte-width atomic builtins remain unsupported, as do global initializers
  requiring conversion of a symbolic pointer address to an integer constant.
  This adds a C99 scalar type, not blanket C99 conformance.
* Ordinary character constants and narrow string literals reuse shared lexer
  escape decoding and adjacent literal concatenation. Strings decay to +char *+
  and have static lifetime; +sizeof("text")+ includes the trailing zero, including
  embedded-zero bytes. Identical decoded strings share storage in this bounded
  backend. Literal bytes are copied from the ROM data payload to RAM by guest
  startup, not retained in a separately protected read-only section. Modifying
  string literals has undefined C behavior and is not runtime-checked.
  Every distinct source literal, including array initializers and unevaluated
  uses, consumes eight-byte-aligned/padded space in the existing 65536-byte
  global budget and contributes to ROM capacity. Oversized storage or ROM output
  diagnoses without overwriting an existing output. Wide literals
  and pointers to whole literal arrays remain
  unsupported.
* Integer promotions, LP64 signed/unsigned mixed arithmetic, scalar conversions,
  explicit integer/pointer casts, assignment expressions, direct
  calls, unary +plus/minus/bitwise-not/logical-not+, binary +add/subtract/
  multiply/divide/remainder/bitwise-and/or/xor+, shifts, and signed/unsigned
  comparisons. Shifts promote each operand independently and retain the
  promoted left operand's type; right shift of negative signed values is
  arithmetic. Unsigned arithmetic wraps at its type's width.
  Signed narrowing retains low bits and interprets the result as two's
  complement. Division by zero, signed arithmetic overflow, and negative or
  out-of-width shift counts have no defined C result and are not runtime-checked.
  Logical +&&/||+ evaluate the left operand first, skip the right when
  appropriate, and produce +int+ zero or one. Conditional +?:+ evaluates
  its condition once and exactly one result arm. Integer arms use the LP64
  common type; compatible object/void-pointer arms and pairs of void expressions are
  supported. Both arms are semantically checked even when an arm cannot
  execute. Null-pointer constant arms retain the other pointer arm's type.
* Compound assignments `+=`, `-=`, `*=`, `/=`, `%=`, `<<=`, `>>=`,
  `&=`, `^=`, and `|=` support integer
  objects using the same promotions and operation types as binary arithmetic,
  followed by conversion to the destination type. Pointer objects support
  `+=` and `-=` with integer element offsets. Prefix/postfix `++` and `--` support the
  same scalar locals and dereferenced objects. Each operation evaluates its
  destination address once, reads the old value once, and writes once;
  aligned temporaries preserve the address and old value across nested calls.
  Prefix/compound expressions return the converted new value; postfix
  expressions return the old value. These operations are not atomic and add
  no synchronization or ordering beyond ordinary guest accesses.
* The supported scalar pointers allow pointer-plus-integer,
  integer-plus-pointer, and pointer-minus-integer with element strides of
  1, 2, 4, or 8 bytes. Subscripts (including negative indices and +i[p]+) lower
  through the same address rules and load/store widths. Pointer subtraction
  requires matching pointee integer types and returns a signed 64-bit element count.
  Matching pointee types support equality and unsigned address ordering;
  pointer conditions and logical-not test against zero. Explicit pointer-to-
  integer casts preserve the address bits before destination-width conversion.
  Integer-to-pointer casts preserve the integer's extended address bits.
  These operations do not check object bounds or pointer provenance; valid
  C array bounds and representable pointer differences remain the guest's
  responsibility. Pointer conversions may add const or volatile qualification
  implicitly; removing it requires an explicit cast. Comparisons, subtraction,
  and conditional expressions accept matching pointee types with either
  qualification; conditional results retain the union of const/volatile qualifiers.
  Casts between different pointee integer types and implicit nonzero/runtime integer-pointer conversions
  remain unsupported. This is not
  complete C pointer support.
* Ordinary +void *+ and its const/volatile-pointee variants are eight-byte scalar object pointers.
  They convert implicitly to/from pointers to supported integer objects while
  retaining const/volatile qualification; removing qualification requires an explicit
  cast. Locals, parameters/results, globals, static object-address initializers,
  explicit integer-address casts, conditions, equality/inequality, and +sizeof+
  reuse existing scalar-pointer lowering. Mixed object/void-pointer conditional
  arms yield +void *+ with the union of both arms' const/volatile qualifications.
  Void-pointer arithmetic, subtraction, updates, subscripting, dereference,
  and ordered comparisons diagnose because void has no complete object size.
  Different integer-pointer types still require an explicit intermediate
  +void *+ cast; function pointers do not convert to/from object pointers.
  Implicit nonzero/runtime integer-pointer conversions remain unsupported. Converting an
  address does not establish valid alignment, bounds, lifetime, or aliasing.
* Const-pointee pointers (such as +const char *+ and +const volatile int *+)
  expose read-only views of the supported integer/void types without changing
  storage width or address bits. Loads use the unqualified scalar value type;
  address-of dereferences/subscripts retains the pointer's qualifiers.
  Direct/compound assignments and prefix/postfix updates through these views
  diagnose, including in unevaluated or unreachable expressions. The pointer
  objects themselves remain writable and may advance through an array.
  Locals, globals, parameter/results, compatible static address initializers,
  null conversions, casts, comparisons, and conditional arms share the
  qualified-pointer rules. Two-level pointers preserve the inner pointer's
  exact qualifiers: +int **+ cannot implicitly become +const int **+, and
  +const int **+ cannot become +const volatile int **+. Tables may contain
  const-pointee entries, and those entries may be reassigned independently of
  the read-only integer objects they reference.
  Explicit casts can remove qualification; guest code remains responsible for
  not writing actual const objects or string literals. This is compile-time
  view checking, not runtime RAM protection.
  Outer pointer-object qualification remains unsupported, including qualified
  pointer typedef uses and abstract pointer-qualified cast/sizeof types.
  The text fixture uses const banner/high-byte arrays and a const-pointee cursor,
  fragment table, and UART helper,
  retaining its exact UART and reported memory results.
* Const/volatile qualifiers apply to supported integer scalar objects and
  one-dimensional integer array elements, including +_Bool+. Global,
  automatic, and parameter objects retain qualifiers through address-of;
  arrays decay to correspondingly qualified element pointers. Reads produce
  unqualified scalar values, and casts/sizeof accept qualified scalar types.
  Initialization may write const storage; later direct/compound assignments
  and prefix/postfix updates diagnose, even in unreachable/unevaluated code.
  Volatile objects use declared-width loads/stores on every evaluated access;
  aliases observe updates, and skipped expressions/sizeof do not read them.
  Top-level parameter/result qualifiers do not change call compatibility or
  the scalar ABI, but a const parameter cannot be changed in its definition.
  Compatible global redeclarations must retain object qualifiers.
  Integer object typedefs preserve these rules. Const data uses the existing
  guest-owned RAM copy/BSS initialization and storage budgets, not a protected
  read-only section. Pointer-object qualification, records, qualified void
  objects, and runtime protection of explicitly cast-away const remain unsupported.
* File-scope typedefs name supported qualified/unqualified integer types, +void+, or
  pointers to supported integer types/void, including const/volatile pointees.
  Alias chains, function
  signatures, global/automatic objects, array elements/bounds, casts, and
  +sizeof+ reuse the shared parser's resolved types; aliases do not create
  distinct types. Volatile-qualified pointee uses of integer aliases such as
  +(volatile u16 *)+ are supported. Unsupported alias targets diagnose even
  when unused. Block-scope/array/function typedefs,
  qualified uses of pointer aliases, duplicate typedef names, and typedef
  names reused by objects, functions, locals, or parameters diagnose.
  Typedef names are reserved across this source unit; inner-scope shadowing
  is not implemented. Target headers and macros use the Rust preprocessor
  described below; this does not add unsupported typedef targets.
* Anonymous file-scope +enum { NAME = expression, NEXT };+ declarations provide
  signed 32-bit +int+ constants. Explicit values use the RV64 LP64 integer
  evaluator, including prior enumerators, casts, +sizeof+, unsigned wrapping,
  and short-circuit expressions; undefined arithmetic or values outside
  +-2147483648..2147483647+ diagnose. Implicit values start at zero or increment
  the preceding value; trailing commas are accepted. Constants retain +int+
  type in runtime expressions and allocate no object storage. They are visible
  only after declaration, including to later enum values, array bounds, globals,
  and functions. Duplicate names and collisions with typedefs/objects/functions/
  parameters/locals diagnose; enumerator shadowing is not implemented.
  Tagged enum types, enum objects, enum typedefs, block enums, and nonconstant
  initializers remain unsupported. Legacy SC-16 enum evaluation is unchanged.
* Address-of supports automatic integer/pointer locals and parameters, dereferences,
  and indexed lvalues. Integer objects keep stable eight-byte private stack
  slots, but aliased loads/stores use their declared byte/halfword/word/doubleword width.
  Address-of a dereference or subscript computes the address without reading
  the object; pointer/index side effects still execute once. Address-of a
  supported one-level pointer object produces a two-level pointer; deeper
  pointer types and address-of non-lvalues diagnose.
  Guest code remains responsible for object lifetime and valid bounds.
* +sizeof(type)+ and +sizeof expression+ return +unsigned long+ constants:
  byte 1, halfword 2, integer word 4, long/pointer 8. Expressions are semantically checked
  without emitting calls, updates, or volatile reads. Void and unsupported
  types diagnose. An array name (including parentheses) retains its full
  byte size under +sizeof+; elsewhere it decays to an element pointer.
  Array parameters are adjusted to pointers, so their +sizeof+ is 8.
  Array type names, variable-length types, and aggregate sizes are not implemented.
* One-dimensional automatic arrays of supported qualified/unqualified integer or one-level pointer elements
  occupy contiguous byte/halfword/word/doubleword storage. Each object starts on an
  eight-byte boundary. Nonempty initializer lists convert each element,
  evaluate explicit initializers left-to-right, and zero-fill omitted elements;
  omitted bounds are inferred from the highest initialized index plus one. Scalar braces around
  individual elements are accepted. Uninitialized arrays are not zero-filled.
  Bounds use scope-independent LP64 integer constant expressions, including
  casts, type +sizeof+, arithmetic, comparisons, and short-circuit expressions;
  unsigned wrapping and signedness match the RV64 expression types.
  Undefined constant arithmetic, nonpositive lengths, and oversized storage
  diagnose. Names and +sizeof(local)+ in bounds remain unsupported.
  Array elements reuse pointer indexing, assignment, and update lowering.
  Arrays cannot be assigned or incremented. Multidimensional arrays,
  pointers to whole arrays (+&array+), empty-list
  initialization, and aggregate elements remain unsupported.
  C99-style array designators (+[constant] = value+) select an element and
  resume subsequent undesignated entries at the next index. Sparse holes
  zero-fill; explicit expressions still evaluate once in source order,
  including out-of-order designators. Indices use scope-independent LP64
  integer constant expressions, including enumerators, casts, type +sizeof+,
  and valid short-circuit arithmetic, and must be nonnegative and below
  65536. Actual element-width, frame/RAM, and ROM budgets still apply.
  Repeated indices (including a following positional entry that overlaps),
  runtime indices even in skipped expression arms, out-of-bounds entries,
  nested/member designators, and designators on scalars diagnose.
  Legacy SC-16 parsing still rejects array designators explicitly.
  Character arrays accept string initializers, optionally surrounded by scalar
  braces: omitted bounds include the terminator, larger arrays zero-fill, and
  an exact byte-length bound may omit the trailing zero. A smaller bound diagnoses.
* File-scope qualified/unqualified integer scalars, scalar pointers to void or the supported
  integer types (including volatile-qualified pointees), and one-dimensional integer arrays
  have persistent RAM storage. Supported integer constant initializers use
  LP64 typing, conversions, optional scalar braces, and the same array-list
  rules as automatic arrays; omitted array elements are zero-filled.
  +sizeof+ may reference the declared object itself or earlier objects.
  Uninitialized definitions (including repeated compatible tentative
  declarations) are zeroed before +main+. One initialized definition may
  accompany compatible tentative declarations. Conflicting types/lengths,
  multiple initialized definitions, and object/function name collisions
  diagnose. Objects must be declared before use and local scopes may shadow
  them. Record globals, dynamic initializers and separate-unit linkage remain
  unsupported.
* File-scope +static+ objects/functions have internal linkage; +extern+
  declarations inherit prior linkage or introduce external linkage. Function
  declarations without a storage class also inherit earlier linkage, while
  object declarations without one have external linkage. Conflicting linkage,
  incompatible types/lengths, duplicate definitions, and internal +main+
  diagnose. Static function definitions and direct/recursive calls use private
  assembly labels; external function names retain their existing ABI symbols.
  Extern object declarations without initializers do not define or duplicate
  storage, but remain visible for later expressions and symbolic address
  initializers. An initialized extern object is a definition; compatible
  tentative definitions still share one object. Every declared object/function
  must have a definition in the source unit, even if unused. This raw-ROM path
  has no external symbol resolution, ELF visibility, or separate-unit linker.
  Extern array bounds must be complete. Block-scope +static/extern+, incomplete
  tentative arrays, and other unsupported storage classes still diagnose.
  The text fixture executes private initialized arrays, its persistent pointer
  cursor, inherited extern object declarations, and a private UART helper.
* Scalar pointer globals accept addresses of previously declared integer
  objects, array decay, indexed element addresses, and constant element
  offsets through the existing typed pointer rules. Symbolic object addresses
  are resolved after final RAM placement, including when a later initialized
  definition moves a previously tentative object into the data region.
  Qualification conversions and conditional selection with an integer
  constant condition are supported. Explicit integer constant casts support
  null, full-width addresses, and MMIO; implicit nonzero/runtime integer conversions
  remain unsupported. Loading another pointer global is not a constant
  initializer. Pointer-to-integer address initializers, integer-to-pointer
  casts through symbolic integer expressions and references before declaration diagnose.
  Runtime pointer-global assignment, dereference, indexing, and updates use
  the same scalar rules as locals. No bounds/provenance checks are added.
* Automatic/global one-dimensional arrays of one-level integer/void pointers
  use contiguous eight-byte elements, including pointers to volatile integer
  pointees. Initializer lists accept compatible scalar addresses and literals;
  omitted entries and explicit null-pointer constants are null.
  Global symbolic entries resolve individually after final RAM
  layout; initialized tables are copied from ROM and tentative tables are
  cleared by guest startup. Two-level pointers (such as +char **+ or
  +volatile int **+) support decay, indexing, dereference, address-of pointer
  objects/elements, scaled arithmetic/differences, comparisons, assignments,
  updates, globals, aliases, and scalar parameter/return conventions.
  Nested pointee qualification must match: +int **+ does not convert implicitly
  to +const int **+, +volatile int **+, or +void **+. Outer pointer-object qualification, three
  or more pointer levels, arrays of two-level pointers,
  and pointer-to-array types remain unsupported.
  Tables count eight bytes per element against existing RAM/frame budgets.
  The text fixture traverses an inferred-bound string/address table terminated
  by an explicit fourth zero entry, rather than a fixed entry count.
  Out-of-order array designators place the ready fragment at index two
  before the banner/positional ROM fragment and null sentinel. It
  reports its address at +0x80000018+; tests inspect each entry and
  its exact pointed-to text while preserving established UART output.
* Null-pointer constants include supported integer constant expressions with
  value zero and those expressions cast to ordinary +void *+. They convert to
  every supported pointer type in initialization, assignment, parameters,
  returns, equality/inequality, and conditional arms. A pointer paired with a
  null constant in +?:+ retains the pointer type and its qualification, rather
  than becoming a void pointer. Constant evaluation uses LP64 rules; runtime
  integers (even if zero) and nonzero integer constants do not convert
  implicitly. Relational pointer/integer comparisons still diagnose.
  Recognition is deliberately bounded to integer literals, enumerators,
  integer casts, +sizeof+, unary/binary integer operations, and logical/
  conditional expressions whose operands are all integer constants. Runtime
  operands in skipped branches are not accepted as null constants.
  The target +<stddef.h>+ defines +NULL+ as +((void *)0)+ using this path.
  Floating constant casts remain unsupported;
  this is not blanket C constant-expression support.
* Automatic scalar locals, nested scopes, compound/expression/return
  statements, +if/else+, +while+, +do-while+, and +for+ (including omitted
  clauses and scoped C99 declaration initializers). +break+ targets the
  innermost loop or switch; +continue+ targets the innermost loop, including
  from inside a switch, and reaches a +for+ update or
  +do-while+ condition before the next iteration. These jumps are statements,
  not expression-level nonlocal exits. Each function has at most 120
  eight-byte parameter/local storage slots (960 bytes): scalars consume one,
  arrays consume their byte size rounded up to eight, and nested scopes share
  this budget without slot reuse. Records, unsupported enum/typedef forms, storage
  class specifiers on block declarations, qualified pointer objects, and other unsupported constructs
  diagnose. C99-style +for+ declarations are not a C90 conformance claim.
* +goto name;+ and named statement labels are function-scoped, including
  forward/backward targets in nested compounds, loops, and switch case bodies.
  Each label emits a private function-unique assembly target. Duplicate labels
  and missing targets diagnose even in unreachable statements; labels in
  another function cannot satisfy a jump. Labels have a separate namespace
  from objects, functions, typedefs, and enumerators, but cannot use keywords.
  Jumps preserve the function's fixed frame and ordinary lexical name lookup.
  Entering a scope can bypass initialization; callers must not read objects
  whose initialization was skipped. Reentering a declaration executes its
  initializer again. Variable-length arrays remain unsupported, so no dynamic
  scope storage or VLA cleanup is implemented. A label must precede a statement
  (use an empty statement before a declaration). Computed goto, label-address
  expressions, cross-function jumps, and nonlocal jump library calls remain
  unsupported. These are C control-flow statements, not GNU computed jumps.
* +switch+ evaluates its integer selector once and applies integer promotions.
  Case expressions use the existing LP64 constant evaluator and convert to
  the promoted selector type before comparison and duplicate detection.
  Signed/unsigned 32/64-bit cases and narrow selectors execute through a
  linear comparison dispatch, not a jump table. Empty switches, grouped
  labels, fallthrough, defaults at any position, recursive returns, and nested
  loop/switch exits are supported. Cases share one switch scope; nested
  compounds retain their own scopes. Noninteger selectors/cases, nonconstant
  or undefined case arithmetic, converted duplicates, duplicate defaults, and
  misplaced exits diagnose. The shared parser requires a braced switch body
  with case/default labels at its top level; statements before the first label
  and labels buried in other statements (including Duff's device) remain
  unsupported.
* GNU +__atomic_load_n+, +__atomic_store_n+, and +__atomic_exchange_n+
  accept ordinary or volatile-pointee pointers to signed/unsigned +int/long+.
  Loads also accept const-pointee variants; stores/exchanges reject read-only
  pointees before emitting an atomic instruction.
  Load and exchange return the normalized pointee type; store returns void.
  Pointer and value operands execute once, in source argument order, including
  across nested calls. The memory order must be an integer constant:
  0 relaxed, 1 consume (implemented as acquire), 2 acquire, 3 release,
  4 acquire-release, or 5 sequentially consistent. Loads reject release and
  acquire-release; stores reject consume, acquire, and acquire-release.
  Loads emit +lr.w/d+ and stores/exchanges emit +amoswap.w/d+, using +aq/rl+
  bits appropriate to the order. Sequentially consistent operations add full
  +fence+ instructions before and after the atomic instruction; this is a
  conservative implementation, not an optimized lowering.
  The existing one-hart CPU executes atomics synchronously against aligned RAM
  and traps on misaligned or non-RAM addresses; loads leave an LR reservation,
  without exposing it as a C value. Exact instruction ordering bits, fences,
  object bytes, lock contention, and acquire/release publication execute in
  tests. This does not certify a multi-hart memory model.
  Byte/halfword, pointer-valued and aggregate atomics, runtime memory orders,
  compare-exchange, other arithmetic atomic builtins, and +_Atomic+ remain unsupported.
  Supported builtin names are reserved, not callable user symbols.
* GNU +__atomic_fetch_add(pointer, value, order)+ and
  +__atomic_fetch_sub(pointer, value, order)+ accept modifiable ordinary/volatile
  pointers to signed/unsigned +int/long+. The value converts to the pointee type;
  one +amoadd.w/d+ returns the old value and updates exactly four/eight RAM bytes.
  Subtraction negates the converted operand before issuing the atomic add.
  Both signed and unsigned atomic arithmetic wrap in two's complement at the
  object width, including subtraction of the signed minimum; this does not
  change the undefined-overflow rules of ordinary signed C arithmetic.
  Word instruction results sign-extend at ISA level and are normalized to the
  declared signed/unsigned result type by the compiler.
  All six constant memory orders use the existing ordering bits/fences;
  consume is acquire and sequential consistency uses full fences immediately
  around the atomic instruction. Pointer/value expressions execute once in
  source order through aligned temporaries, including nested and stack calls.
  Const pointees, byte/halfword/pointer/aggregate values, invalid/runtime
  orders, wrong argument counts, and reserved builtin declarations diagnose.
  Misaligned/non-RAM addresses trap in guest execution. The text helper uses

Startup begins at the ROM reset vector in M-mode, sets +sp+ to +0x80010000+,
copies initialized global bytes from protected ROM to RAM, clears
uninitialized global storage, and calls +int main(void)+.
Global storage occupies at most 65536 bytes in
+[0x80010000, 0x80020000)+, above the downward-growing stack. Objects have
at least eight-byte alignment and their sizes are padded to eight bytes;
initialized objects precede uninitialized objects, with names sorted within
each group. GNU +__attribute__((aligned(n)))+ (also +__attribute+ and
+__aligned__+ spellings) raises a global object's required RAM alignment.
The argument must be a positive LP64 integer constant expression and a power
of two from one through 65536. Smaller requests do not reduce the backend's
eight-byte minimum or change element sizes/array strides.
Attributes before/within declaration specifiers apply to all comma-separated
declarators; attributes after a declarator's array dimensions apply only to
that object. Multiple attributes and compatible static/extern/tentative
redeclarations retain the strongest alignment; weaker later declarations
cannot undo it. These attributes do not change object types or call ABI.
Array bounds inferred from initializers and existing object/callback pointer
initializers use the same path.
Alignment gaps count against the RAM budget. Gaps within initialized storage
are zero bytes in the ROM payload and are copied by startup; gaps before or
within BSS are cleared by startup. Static object pointers and symbolic callback
addresses resolve after the aligned layout is final. Data padding counts
against ROM capacity, too: a RAM-valid initialized layout can still exceed
the raw-ROM limit and must diagnose without replacing an output.
Attributes with missing/default arguments, nonconstant/invalid arithmetic,
non-power-of-two or excessive alignment, unsupported attribute names, and
local/parameter/function/typedef alignment remain rejected. This does not
add aligned stack frames, aligned type aliases, record fields, code alignment,
ELF section alignment, or general attribute/type-layout support.

identify the generated assembly line. Sytyke, the pinned kernel, relocatable
objects, and ELF linking remain separate open requirements.

=== Memory ordering

CPU and device accesses are coherent and ordered according to the RISC-V
memory model and explicit fence instructions. Device DMA may read or write
RAM only, must validate the complete physical range without integer overflow,
and must not bypass PMP, access-fault, or protection checks. No implicit
host-file or host-memory service is part of the guest physical bus.

== Counters and virtual time

+cycle+ and +instret+ are 64-bit counters with architectural privilege-enable
checks; they wrap modulo 2^64. +time+ is a 64-bit monotonically increasing
machine timebase with a 10 MHz frequency. It starts at zero on cold reset and
advances from virtual machine execution, not host wall-clock time, so headless
tests are reproducible. One emulated core cycle advances one timebase tick;
idle advancement and timer delivery use the same virtual clock. Timer compare
and pending state are evaluated against that counter without 32-bit truncation.

RTC civil time is not the +time+ CSR and does not change this monotonic timer
contract. Any later wall-clock device has a separate interface and cannot
replace Sstc or alter the timebase frequency.

The Kiuas16 core currently advances +time+ by one tick for each attempted or
idle core cycle, exposes the read-only CSR with the specified
S/U counter-enable checks, and derives the supervisor timer-pending bit from
+stimecmp+. S-mode access to +stimecmp+ requires +menvcfg.STCE+; M-mode retains
access. The physical bus also contains an initial Vihta PLIC slice with 31
external sources, machine/supervisor contexts, 32-bit priority/pending/enable/
threshold/claim/complete registers, and level reassertion after completion.
Its context outputs feed the core's external interrupt pending state. Höyry
drives source 10; the other board-device sources are not wired yet. The
headless +Kiuas16Machine+ single-step interface now connects this core and bus,
so timer and PLIC behavior use one deterministic execution loop. Timed device
peripherals and a host runtime remain unimplemented. Machine-level tests now
execute an S-mode timer handler that rearms +stimecmp+ and returns to guest
code, and a UART external-interrupt handler that claims the PLIC source,
consumes RX data, completes the claim, and resumes guest execution. Time
advances exactly once per machine step; no host wall clock is consulted.

== Höyry UART

Höyry occupies +0x10000000..0x10001000+ and has an initial
16550-compatible register/FIFO/interrupt implementation with headless input
and output methods. The normative register behavior, source assignment,
unsupported accesses, and implementation gaps are defined in
link:kiuas16_device_contract.adoc[the device contract]. Timed transmission,
full modem/line behavior, runtime adapters, and pinned xv6-driver acceptance
remain open.

== Limits and conformance

The initial configuration has exactly one hart and 128 MiB of RAM. Multicore,
hypervisor/vector extensions, 32-bit execution, physical address aliasing,
and implicit legacy SC-16 devices are outside this contract. The machine is
not advertised as real Linux or as complete RISC-V platform compatibility.

The +nx-machine-contract+ roadmap item tracks completion of this target
specification and its physical-boundary, reset, and capability fixtures; it
does not claim implementation of every architectural requirement above.
Current tests cover reset values and ROM access, the full-width physical
address boundary, configured RAM limits and unmapped holes, one-hart
capability reporting, partial privilege transitions, Sv39 faults and ADUE
updates, the implemented PMP entry, Sstc compare/interrupt behavior, and DMA
boundary rejection. They must show failed accesses do not wrap, alias, or
partially commit. Full RV64GC and xv6 handoff conformance remain separate
implementation gates; the pinned kernel handoff is tracked by the BIOS tasks.
