= SuomiCPU-16

SuomiCPU-16 is an emulator for the SC-16, a small, byte-addressed machine.
Runtime, tools, and tests are implemented in Rust.

== Features
* Full emulation of the SC-16 architecture.
* Integrated assembler for SC-16 assembly language.
* C90-oriented compiler for SC-16 with partial language/preprocessor and
  standard-library support (+setjmp.h+ and +signal.h+ are not implemented),
  plus a target-specific C99 +<stdint.h>+ header
  (not a fully conforming C90 implementation; see the
  link:docs/user_guide.adoc#9-ansi-c90-compiler[user guide]).
* Memory-mapped console, BIOS folder-disk boot selection and guest filesystem,
  legacy JSON disk import, a layered GPU with 640x480x4-bit VRAM, hardware
  tile/sprite engines, and a fixed-point 3D graphics coprocessor.
* Keyboard, RTC, and programmable instruction-timer interrupts for
  software-managed task scheduling.

== Getting Started
Install Rust and Cargo, then start the emulator with:

[source,console]
----
cargo run --bin suomicpu16
----

Start SC-16 without arguments to execute the required shared +firmware/bios.bin+ and
show the text-mode BIOS disk selector.
Use *Up/Down* and *Enter*, or click and double-click, to boot an ID-named
folder under +disks/+. The mouse wheel scrolls the list. The selected disk
must have valid +disk.json+ metadata and exactly one boot executable:
+kernel.bin+ starts in KERNEL mode; +main.bin+ starts in USER mode.
Both or neither produces +NOT_BOOT+; errors remain visible so another disk
can be selected. BIOS loads prebuilt SC-16 images without compiling source.
Use +--disk ID+ to preselect a folder boot disk in BIOS or mount that folder
filesystem alongside a directly launched program. Legacy JSON block disks are
kept only as import sources; use +sc16build import-block-disk+ to convert them.
See +docs/sc16_disk_format.adoc+ for the folder format and kernel-code trust
model.
In windowed mode, the *BUG MONITOR* toolbar button opens emulator diagnostics
in a separate resizable window. Press *F2* to toggle it. There are no host
pause, stop, reset, or reboot controls; F1, F3, F4, and F5 are not host shortcuts.
Close and relaunch the emulator to start a new session.
Use _Shift+Ctrl+F_ to toggle windowed/fullscreen mode (*F11* is also
supported). The toolbar and console window are closed in fullscreen mode.
Start directly in fullscreen with
+cargo run -- --fullscreen+ or +.\run.ps1 -Fullscreen+.
Detailed stage logs are on by default and show which SC-16 component is
processing each source file, including compiler, assembler, include, and
memory-loading stages. Use +--quiet+ to hide these details.

== Programs and repository layout

Guest workloads live in +programs/<slug>/+, each with its own sources, tools,
and +program.json+ build recipe. The Rust emulator is in +src/emulator/+;
assembler/compiler implementations are in +src/assembler/+ and
+src/c_compiler/+. Shared tools are in +src/tools/+, guest libraries in
+toolchain/+, and BIOS/fonts in +firmware/+. Educational +examples/+ are
not installed programs.

[source,powershell]
----
.\scripts\build-programs.ps1 sisuos -Install
.\scripts\build-programs.ps1 -Install
.\run.ps1 .\disks\sisuos
----

See link:docs/programs.adoc[Building, installing, and migrating programs] for
the per-program/all-program commands, manifests, and safe disk updates.
Program disk names and IDs now match their slugs. Data disks +DISK0001+ and
+DISK0002+ are unchanged.

== SisuOS

The checked-in +disks/sisuos+ folder is a small protected, preemptive OS
demonstration. Start the emulator with +--disk sisuos+, then press Enter in
the BIOS to boot its trusted +kernel.bin+. The kernel enables the MMU and
instruction timer before starting the user-mode SisuOS shell. The shell
supports +help+, +list+, +info+, +ps+, +run demo+, and +run demo X+.
The timed form runs a background child for X seconds, printing
+BGP [pid] time [second]/X+ each second while the shell remains responsive.
This is a tested demonstration, not a general-purpose OS.

To rebuild and install while preserving unrelated writable disk data:
[source,powershell]
----
.\programs\sisuos\tools\build.ps1 -Install
----
The script builds the C shell, C demo and assembly bootstrap from
+programs/sisuos/src/+ using +sc16build+,
packages the folder manifest and protects both executable files. Its output
is a valid boot disk; the BIOS integration test checks the checked-in images
against these sources and exercises the shell and preempted demo.

Run an example directly from the repository root:
[source,console]
----
cargo run --bin sc16build -- examples/example.asm example.sc16img
cargo run --bin suomicpu16 -- example.sc16img
----

For five analog clock styles, a Nixie-tube display, and a flip clock, run:
[source,console]
----
cargo run --bin sc16build -- programs/anaclock/src/anaclock.c anaclock.sc16img
cargo run -- anaclock.sc16img
----
Press Tab to cycle through the seven clock faces.

For a first-person Elite-style space combat demo, run:
[source,console]
----
cargo run --bin sc16build -- programs/elite/src/elitedemo.c elitedemo.sc16img
cargo run -- elitedemo.sc16img
----
Turn with Left/Right, increase or decrease throttle with Up/Down, and fire with
Space. The ship accelerates and drifts with inertia; shields regenerate and the
laser needs time to cool.

Launch *Hertta-3D* directly with +programs/hertta-3d/src/hertta3d.c+, or package
it into a folder disk for BIOS boot, for a first-person maze game rendered with the
SC-GPU. Use W/S to move, A/D to turn, and Space to throw treats toward Hertta;
feed her enough treats and wait for her to reach you to advance to a harder
maze. Each visible wall cell is rendered as one outlined surface, and a solid-cell
minimap shows the connected maze and marks you and Hertta. Hertta wanders through
the passages and can find a path to you after eating enough treats. Its source is
link:programs/hertta-3d/src/hertta3d.c[+programs/hertta-3d/src/hertta3d.c+].

On Windows, the PowerShell launcher can run the same programs:
[source,powershell]
----
.\run.ps1 .\examples\example.asm
----
It changes to the repository directory and starts the Rust emulator through
Cargo. Make sure Rust and Cargo are available on +PATH+.

The emulator accepts assembly (+.asm+), C (+.c+), and flat binary (+.bin+)
programs. Assembly is built natively by Rust. The Rust C compiler currently
handles multiple +int+ functions and +void+ helpers with up to three parameters,
local +int+ variables, scalar global integers, and indexed global integer
arrays, brace initializers for integer globals and arrays, assignments,
scalar integer typedef aliases, translation-unit enum constants and enum-typed
integer declarations,
object-like +#define+ macros and +#undef+, prefix/postfix increment and
decrement, arithmetic/bitwise/shift/logical and
signed comparison expressions, conditional and comma expressions, +if+/+else+,
+switch+ with case fallthrough, +goto+ labels, nested
blocks, basic integer +sizeof+, and +while+/+do+/+for+ loops with +break+ and
+continue+, including recursive calls. Programs outside this subset are rejected
with a Rust compiler diagnostic; C sources are compiled only by Rust.
Object-like macros, +#undef+, and
+#if+/+#elif+/+#ifdef+/+#ifndef+ conditional branches are preprocessed.
Quoted includes search beside the including source; angle-bracket includes
search the repository +toolchain/include/+ directory. Function-like macros support argument
substitution, stringification, and token pasting; backslash-newline source
continuations are also supported. Variadic macros are not implemented in Rust
yet. To compile a C file into a segmented image:

[source,console]
----
cargo run --bin sc16build -- programs/asteroids/src/asteroids.c asteroids.sc16img
cargo run -- asteroids.sc16img
----

See the link:docs/user_guide.adoc[user guide] for setup details, controls, and the full
example catalog.

== Rust emulator port

The Rust port uses Macroquad for graphics and can be compiled for native
systems or +wasm32-unknown-unknown+:

[source,console]
----
rustup target add wasm32-unknown-unknown
cargo build --target wasm32-unknown-unknown
----

The browser build is not yet a standalone web release: program discovery and
program file access still rely on the host filesystem. Rust builds +.asm+
programs with its native assembler and compiles the documented subset of +.c+
files directly. Unsupported C programs are rejected.

Run a program with optional persistent data-disk and LAN settings:

[source,console]
----
cargo run -- --disk netgame-demo --net-port 47016
cargo run -- --headless disks\disk-editor
----

Build an SC-16 source file into a segmented image using the Rust tools:

[source,console]
----
cargo run --bin sc16build -- build-bios
cargo run --bin sc16build -- examples\commands.asm
cargo run --bin sc16build -- examples\example.asm example.sc16img
cargo run --bin sc16build -- input.bin output.sc16img
cargo run --bin sc16build -- build-programs
cargo run --bin sc16build -- install-programs
cargo run --bin sc16build -- import-block-disk disks\DISK0001.json build\DISK0001
.\scripts\build-programs.ps1 sisuos -Install
----

The checked-in slug-named disks contain 18 prebuilt programs, including SisuOS
and Tank-16's runtime assets. +build-programs+ writes staging output under
+build/programs/+; +install-programs+ updates package-owned outputs and preserves
writable disk data, reporting conflicts instead of overwriting local edits.
BIOS and program builds are offline host tools; the guest BIOS only loads
prebuilt disk images.
DiskEditor is a USER-mode text-file editor for the currently mounted folder
disk. It creates or updates files up to 256 bytes and respects disk read-only
and protected-file policies.

In the Rust BIOS selector, choose a folder boot disk with *Up/Down* and
*Enter*. +--disk ID+ preselects that boot disk; with an explicit program path
it mounts the same folder filesystem for guest file operations.

Original block-disk JSON files remain in +disks/+ only as import sources;
converted folder disks are stored alongside them without modifying originals.
The emulator accepts prebuilt +.bin+ or +.sc16img+ files and validated disk
folders; it does not compile source during launch. +run.ps1+ can accept a C or
assembly source path and invokes +sc16build+ first to create a temporary
prebuilt image, then removes that image after the emulator exits. Direct
source launches through +run.ps1+ use the source program's +disks/+ data folder
as a read-only mount. BIOS-booted applications use the selected folder disk
and its guest filesystem service. Networking uses UDP broadcast on the
selected port in native builds; browser builds do not provide UDP networking.

Regenerate the animations for every bootable folder disk:
[source,console]
----
cargo run --bin sc16gallery
----
Each generated GIF loops continuously with a 15-second cycle by default.
The Rust CPU runs the prebuilt disk image for 10 simulated seconds during capture.
Use
+--run-seconds+ to change the capture window and +--gif-seconds+ to set the
total GIF duration; +--fps+ and +--capture-fps+ adjust sampling. The command
discovers validated disk manifests from +disks/+ each time it runs and updates
this gallery. It does not compile program sources.
