= SuomiCPU-16

SuomiCPU-16 is an emulator project with the *Kiuas16* processor and *AinoGPU*
graphics device. The current implementation uses the legacy SC-16
byte-addressed architecture. Runtime, tools, and tests are implemented in Rust.

== SC16NX direction

The sole development checklist is the
link:docs/sc16nx_todo.adoc[SC16NX roadmap]. It targets RV64-compatible Kiuas16,
Rust-built xv6, PC-like BIOS firmware, Finnish-named hardware, AinoGPU
hardware-accelerated 3D, and working xv6 versions of all 17 active programs.
These are planned capabilities, not features of the current emulator.
SisuOS/SaunaShell remains a frozen source example, not an OS being developed
or ported to the successor machine.

The separate +kiuas16-run+ command executes an explicitly supplied RV64 ROM
headlessly with optional raw-sector media and scripted serial input. It is
an initial hardware runner, not the finished Sytyke BIOS or an xv6 boot path.
See the link:docs/kiuas16_machine_contract.adoc#headless-runner[headless runner]
for its input format, bounded execution, and media safety rules.

The Rust +kiuas16-asm+ command builds raw ROMs from an initial RV64 assembly
subset. See the
link:docs/kiuas16_machine_contract.adoc#rom-assembler[ROM assembler] for
commands, supported syntax, and the source-built storage execution fixture.
It is not yet a C compiler, relocatable-object assembler, or ELF linker.

The separate +kiuas16-cc+ command now compiles a small freestanding C subset
through typed RV64 lowering and that ROM assembler. Its
link:docs/kiuas16_machine_contract.adoc#rom-c-compiler[compiled guest fixtures]
execute UART and guest-owned storage operations, including LP64 signed/unsigned
integer arithmetic, full-width literals, shifts, and volatile MMIO. This is initial bring-up,
not the complete xv6 compiler or ELF build pipeline.

== Current SC-16 features
* Full emulation of the SC-16 architecture.
* Integrated assembler for SC-16 assembly language.
* C90-oriented compiler for SC-16 with partial language/preprocessor and
  standard-library support (+setjmp.h+ and +signal.h+ are not implemented),
  plus a target-specific C99 +<stdint.h>+ header
  (not a fully conforming C90 implementation; see the
  link:docs/user_guide.adoc#9-ansi-c90-compiler[user guide]).
* Memory-mapped console, BIOS folder-disk boot selection and guest filesystem,
  protected console and graphics services, and high-bank device interfaces
  including a discoverable serial UART.
* Keyboard, UART, RTC, and programmable instruction-timer interrupts for
  software-managed task scheduling.

== Getting Started
For the ordered setup and first-run guide, see
link:docs/getting_started.adoc[Getting Started]. In brief, install Rust and
Cargo, then start the emulator with:

[source,console]
----
cargo run --bin suomicpu16
----

Starting without arguments executes the required shared +firmware/bios.bin+
and opens the BIOS disk selector. Choose an ID-named folder under +disks/+;
the BIOS validates its manifest and launches its fixed boot executable.
For first-time users, BIOS controls, SisuOS, and build/install steps, follow
the dedicated guide linked above. The
link:docs/sc16_disk_format.adoc[folder-disk specification] and
link:docs/sc16_architecture.adoc[machine architecture] define the enforced
contracts.

The emulator creates a fresh machine state and starts the common BIOS from
reset vector zero before disk selection and OS handoff. Folder-disk contents
and BIOS settings persist across emulator sessions; RAM and device state do
not. Press F3 to open the separate serial monitor; type in the main emulator
window to send UART input. The F2 Bug Monitor remains dedicated to emulator
diagnostics.

== Programs and repository layout

Guest workloads live in +programs/<slug>/+, each with its own sources, tools,
and +program.json+ build recipe. The Rust emulator is in +src/emulator/+;
assembler/compiler implementations are in +src/assembler/+ and
+src/c_compiler/+. Shared tools are in +src/tools/+, guest libraries in
+toolchain/+, and BIOS/fonts in +firmware/+. Educational +examples/+ are
not installed programs.

[source,powershell]
----
.\run.ps1 .\disks\sisuos
.\scripts\build-install.ps1 <active-slug>
----

The SisuOS command above launches its checked-in prebuilt disk; its source
manifest is archived and cannot be built or installed by current tooling.
Active program builds and installation use the shared manifest-driven
workflow. Use +.\scripts\build-install.ps1 <active-slug>+ to build and install
a package, or add +-Start+ to launch its installed disk afterward. See
link:docs/programs.adoc[program build and disk details]. Data disks +DISK0001+
and +DISK0002+ are unchanged.

== SisuOS

This section preserves the legacy SC-16 example. The
link:docs/sc16nx_todo.adoc#nx-sisuos-freeze[SisuOS archive boundary] retains
source and revision-bound historical build instructions only; the manifest is
archived, and current build/install commands reject it. Existing disk launches
remain a legacy emulator workflow, not a maintained successor-machine port.

The checked-in +disks/sisuos+ folder is a small protected, preemptive OS
demonstration. Start the emulator with +--disk sisuos+, then press Enter in
the BIOS to boot its trusted +kernel.bin+. The kernel enables the MMU and
instruction timer before starting the user-mode SaunaShell. The shell supports
+help+, +info+, +ps+, +list+, +run PROGRAM [args] [&]+, and +logout+.
+list+ currently names the packaged guest programs; it is not a filesystem
browser. +run daemon &+ starts the blocking daemon in the background, and
+run sleeper+ starts the monotonic timer example. Accounts, permissions,
multiple consoles, and a general-purpose filesystem shell are not implemented.

Historical build/install commands (recorded at revision
+da0a5b54e198b43ea55df756289872440a1df32b+):
[source,powershell]
----
cargo run --bin sc16build -- build-program sisuos
cargo run --bin sc16build -- install-program sisuos
----
Those commands are no longer supported at the current revision. The archived
manifest, C sources, and assembly bootstrap remain available under
+programs/sisuos/+.

Run an example directly from the repository root:
[source,console]
----
cargo run --bin sc16build -- examples/directives.asm example.sc16img
cargo run --bin suomicpu16 -- example.sc16img
----

On Windows, the PowerShell launcher can run the same programs:
[source,powershell]
----
.\run.ps1 .\examples\directives.asm
----
It changes to the repository directory and starts the Rust emulator through
Cargo. Make sure Rust and Cargo are available on +PATH+.

The emulator accepts assembly (+.asm+), C (+.c+), and flat binary (+.bin+)
programs. Assembly is built natively by Rust. The Rust C compiler currently
handles multiple +int+ functions and +void+ helpers with up to three parameters,
local +int+ variables, scalar global integers, and indexed global integer
arrays, brace initializers for integer globals and arrays, assignments,
scalar integer typedef aliases, translation-unit enum constants and enum-typed
integer declarations,
object-like +#define+ macros and +#undef+, prefix/postfix increment and
decrement, arithmetic/bitwise/shift/logical and
signed comparison expressions, conditional and comma expressions, +if+/+else+,
+switch+ with case fallthrough, +goto+ labels, nested
blocks, basic integer +sizeof+, and +while+/+do+/+for+ loops with +break+ and
+continue+, including recursive calls. Programs outside this subset are rejected
with a Rust compiler diagnostic; C sources are compiled only by Rust.
Object-like macros, +#undef+, and
+#if+/+#elif+/+#ifdef+/+#ifndef+ conditional branches are preprocessed.
Quoted includes search beside the including source; angle-bracket includes
search the repository +toolchain/include/+ directory. Function-like macros support argument
substitution, stringification, and token pasting; backslash-newline source
continuations are also supported. Variadic macros are not implemented in Rust
yet. SisuOS remains a legacy guest example; its archived manifest is excluded
from current program builds. See the link:docs/user_guide.adoc[user guide] for
setup details and the supported assembly examples.

== Rust emulator port

The Rust port uses Macroquad for graphics and can be compiled for native
systems or +wasm32-unknown-unknown+:

[source,console]
----
rustup target add wasm32-unknown-unknown
cargo build --target wasm32-unknown-unknown
----

The browser build is not yet a standalone web release: program discovery and
program file access still rely on the host filesystem. Rust builds +.asm+
programs with its native assembler and compiles the documented subset of +.c+
files directly. Unsupported C programs are rejected.

Build an SC-16 source file into a segmented image using the Rust tools:

[source,console]
----
cargo run --bin sc16build -- build-bios
cargo run --bin sc16build -- examples\commands.asm
cargo run --bin sc16build -- examples\directives.asm example.sc16img
cargo run --bin sc16build -- input.bin output.sc16img
cargo run --bin sc16build -- build-programs
cargo run --bin sc16build -- install-programs
----

+build-programs+ and +install-programs+ discover active manifests, skip
archived entries, and write staging output under +build/programs/+. Some active
guest sources still reference removed APIs and fail with an explicit compiler
diagnostic until migrated. Installation preserves writable disk data and
reports conflicts instead of overwriting local edits; the guest BIOS loads
prebuilt disk images.

In the Rust BIOS selector, choose a folder boot disk with *Up/Down* and
*Enter*. +--disk ID+ preselects that boot disk; with an explicit program path
it mounts the same folder filesystem for guest file operations.

Archived block-disk JSON files remain inert in +disks/+; the emulator and build
tools do not load or import them. Folder disks are the only supported format.
The emulator accepts prebuilt +.bin+ or +.sc16img+ files and validated disk
folders; it does not compile source during launch. +run.ps1+ can accept a C or
assembly source path and invokes +sc16build+ first to create a temporary
prebuilt image, then removes that image after the emulator exits. Direct
source launches through +run.ps1+ use the source program's +disks/+ data folder
as a read-only mount. BIOS-booted applications use the selected folder disk
and its guest filesystem service. Networking uses UDP broadcast on the
selected port in native builds; browser builds do not provide UDP networking.

Regenerate the animations for every bootable folder disk:
[source,console]
----
cargo run --bin sc16gallery
----
Each generated GIF loops continuously with a 15-second cycle by default.
The Rust CPU runs the prebuilt disk image for 10 simulated seconds during capture.
Use
+--run-seconds+ to change the capture window and +--gif-seconds+ to set the
total GIF duration; +--fps+ and +--capture-fps+ adjust sampling. The command
discovers validated disk manifests from +disks/+ each time it runs and updates
this gallery. It does not compile program sources.
